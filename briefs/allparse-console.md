解析 API 的控制台，给接入了这个接口的开发者与运营看：密钥与配额、九个平台的可用状态、调用量与错误码分布。

## 产品与用户

- 产品：ALLParse Console，管理解析 API 的密钥、配额与调用情况，覆盖 9 个平台。
- 用户：接入方的后端工程师与对接运营。工程师关心密钥和报错，运营关心配额余量与平台可用性。

## 主任务

确认密钥是否可用与剩余额度，看某个平台是否故障，查最近 24 小时的调用量与错误码分布，定位失败集中在哪个平台和哪个错误码。

## 关键内容

- 密钥：名称、前缀（ak_live_ 或 ak_test_）、创建时间、最近使用时间、轮换与停用状态。
- 配额：套餐总量、已用、剩余、重置时间；免费档每天 1,000 次（演示口径）。
- 平台状态：9 个平台各自的可用、降级、维护，附最近一次状态变更时间。
- 调用量：最近 24 小时按小时聚合，总量与成功量。
- 错误码：401 密钥无效、402 配额用尽、429 触发限流、5001 平台解析失败、5002 上游超时，各带次数与占比。
- 失败样本：时间、平台、错误码、请求 ID、原始链接的截断形式。

## 可用的内容材料

一天的调用明细、错误码字典、平台状态公告、配额账单、几条失败请求样本。

## 假设

- 数据为演示数据，未接真实网关与计费。
- 错误码与配额数值为演示口径。
