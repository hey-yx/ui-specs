# 版式速查（Hallmark 版式库的项目内索引）

来源是 Hallmark skill 的 `references/macrostructures.md` 与 `references/component-cookbook.md`，这里只做选用标准的提炼，避免每次生成去翻二十几个文件。件名与取舍以 Hallmark 版式库为准，本库不存版式全文。

用法：单站生成不先按这张表选件，结构交给 Hallmark 按产品动作定；定稿后记录实际用的件名，供这张表核对，不为了对表改稿。一次生成多站时，才在开批前按表分配以防批内重复，换一批可以重排；候选记进取值记录，不另出第二份页面文件。

## 先判形态，再挑件

| 产品形态 | 首选 | 备选 | 选用标准 |
| --- | --- | --- | --- |
| 营销页（卖点与转化） | Marquee Hero · Feature Stack · Stat-Led | Bento Grid · Quote-Led · Split Studio | 首屏要不要一句主张撑住 |
| 应用页（打开就是工具） | Workbench · Index-First | Stat-Led · Bento Grid | 内容是界面本身，不是产品介绍 |
| 文档与参考 | Long Document · Component Playground | Index-First · Conversational FAQ | 读者来查，不是来被说服 |
| 内容发现（平台价值在浏览） | Ecosystem Index · Catalogue | Bento Grid · Portfolio Grid | 有多条发现路径，不靠一句宣言 |
| 流程型产品 | Narrative Workflow | Long Document | 产品本体就是一串步骤 |
| 个人叙事与宣言 | Letter · Manifesto | Quote-Led | 第一人称或立场先于卖点 |

## 分配时的硬规则

- 同一批内 macrostructure 不重复，nav 不重复，footer 每种最多两次，灰底站点不超过半数（以 `python3 scripts/check-frame.py` 核对 `<meta name="frame">` 与 `DECISIONS.md` 的 `frame:` 行；开新批次时加 `batch=<批次名>` 如 `batch=2026-11-21-b; nav=...`，避免被前序批次的 14 个 nav 编号锁死，同时页脚 DOM 骨架仍全库验重）。
- 默认避开 N1a 与 Ft3：这两个是最容易被认出的模板指纹，只有真的符合才用。
- 挑件规则见 `content/PROJECT-SELECTION.md` 的「版式与配色怎么挑」，本表只做件名索引；页底色、顶栏、页脚随选中选型与产品形态自由组合，不套预制外壳。
- 版式件只是一层，配色另算：强调色在色彩点的色板原文里取，同批色系不少于六种。
- 换件要写理由并记进 FINDINGS，不许悄悄换；落稿收官追加 `.hallmark/log.json`。
