自建 API 网关的控制台，给要管密钥与额度的小团队开发者用：看本月总额度、逐把密钥的用量与限额，把接近阈值的那把调高。

## 产品与用户

- 产品：AnyTTL，团队自建的 API 网关，前端请求经它中转，按密钥计量与限流。
- 用户：3 到 10 人小团队的开发者，兼管额度的负责人；熟悉密钥前缀、HTTP 状态码与限流语义。

## 主任务

确认本月总额度还够不够，找出接近阈值的那把密钥，把它调到不超阈值，改完立刻生效。

## 关键内容

- 额度：本月总请求 1,248,930 次，总额度已用 68%，超阈值密钥 1 个。
- 阈值：单把密钥达到限额 80% 即触发限流，新请求返回 429，响应体带 retry_after；改限额立即生效，按分钟统计。
- 密钥清单：名称、前缀、本月请求、限额（万次）、状态（正常 / 接近阈值 / 已停用），默认按本月请求降序。
- 行内调整：以当前限额为初值，实时算占用比例与余量，保存后更新该行并播报结果。
- 批量操作：勾选后出现批量停用；未勾选时不占位置。
- 状态：空态、加载、读取失败（带错误码）、保存成功四种都要出现。

## 可用的内容材料

密钥前缀（sk- 开头）、限额与请求数、阈值与 429 语义、错误码 upstream_timeout、页脚的支持邮箱与演示声明。

## 假设

- 数字、密钥名与错误码均为演示口径，不接真实网关。
- 价格与结算口径 [待确认]，页面不出现金额。
- 只做密钥与用量一页，日志与设置只在导航里占位。
