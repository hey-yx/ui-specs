Quickstart

Three steps: send a line, read the fields, then query what you stored. The example below uses a real log shape from an API gateway.

  1. 1

    Send a line

    Post one line per request. Batch up to 500 lines with POST /v1/parse/batch when you need throughput.

    request.sh
    curl https://api.payloaddeck.dev/v1/parse \
  -H "Authorization: Bearer $PAYLOADDECK_KEY" \
  -H "Content-Type: application/json" \
  -d '{"line":"2026-11-14T09:41:07Z INFO api-gateway req=8f3c2a status=200 latency_ms=84"}'
  2. 2

    Read the result

    Every field is typed. A missing field is left out, never filled with a guess.

    response.json
    {
  "timestamp": "2026-11-14T09:41:07Z",
  "level": "INFO",
  "service": "api-gateway",
  "request_id": "8f3c2a",
  "status": 200,
  "latency_ms": 84
}
  3. 3

    Query what you stored

    Parsed fields land in a queryable table. Filter by service and status without writing a regex.

    query.sh
    curl "https://api.payloaddeck.dev/v1/events?service=api-gateway&status=5xx&since=24h" \
  -H "Authorization: Bearer $PAYLOADDECK_KEY"

Try a line

This runs against a local fixture. It sends nothing and needs no key.

ISO 8601 timestamp first, then level, service and key=value pairs.

Enter a log line first.

POST /v1/parse

One line in, one event out. Requests are limited by plan, not by concurrency.

request.sh
curl https://api.payloaddeck.dev/v1/parse \
  -H "Authorization: Bearer $PAYLOADDECK_KEY" \
  -H "Content-Type: application/json" \
  -d '{"line":"2026-11-14T09:41:07Z INFO api-gateway req=8f3c2a status=200"}'
parse.mjs
import { PayloadDeck } from "@payloaddeck/sdk";

const deck = new PayloadDeck({ apiKey: process.env.PAYLOADDECK_KEY });

const event = await deck.parse({
  line: "2026-11-14T09:41:07Z INFO api-gateway req=8f3c2a status=200",
});
parse.py
from payloaddeck import Client

client = Client(api_key=os.environ["PAYLOADDECK_KEY"])
event = client.parse(
    line="2026-11-14T09:41:07Z INFO api-gateway req=8f3c2a status=200",
)

Parameters

Request body fields for POST /v1/parse
FieldTypeRequiredNotes
linestringYesOne line, up to 64 KB. Long lines return 413.
formatjson · ndjsonNoDefaults to json. Use ndjson for streams.
rulesstring[]NoExtra patterns for fields your line format needs.
redactstring[]NoField names to replace with [redacted] before storage.

Response time. p50 is 12 ms and p95 is 41 ms for a 1 KB line in the same region. Measured on 14 Nov 2026 with the fixture corpus.

Error codes

Errors return a JSON body with code and message. Retry only the codes marked retryable.

API error codes and fixes
CodeHTTPMeaningFix
invalid_key401Missing or revoked API keyCreate a key in the console, then retry.
invalid_json400Body is not valid JSONCheck quotes and commas before retrying.
line_too_long413Line is over 64 KBTruncate the line or split it at a delimiter.
unparsable_line422No timestamp or level foundSend the raw line, not a pre-formatted summary.
rate_limited429Plan limit reachedBack off for the number of seconds in Retry-After.
internal500Parser failedRetry with jitter. If it repeats, send the line to support.

Rate limits

Limits reset every minute. Burst allows a short spike above the steady rate.

Requests per minute by plan
PlanRequests / minBurstBatch size
Free601050 lines
Pro600100500 lines
Scale6,0001,0005,000 lines

Retries. A 429 response includes Retry-After in seconds. Retry after that delay, then add up to 200 ms of jitter.
