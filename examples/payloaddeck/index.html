The call is synchronous up to 5 MB. Above that, send the file to /v1/jobs and poll the job id — same records, no timeout.

02POST /v1/query

Query what you stored

Fields keep the type PayloadDeck inferred, so you filter on numbers and timestamps without casting them. This returns every checkout that ran longer than five seconds in the last fifteen minutes, whatever level it logged at.

POST/v1/query 200 · 4 rows
records · last 15 minutes · limit 50
tslevelserviceduration_ms
09:14:02errorcheckout-api30012

from records
where service = "checkout-api"
  and duration_ms > 5000
  and ts > now() - "15m"
order by ts desc
limit 50

ts takes relative windows: 15m, 2h, 7d

Send the same query as a JSON body to /v1/query. The CLI writes the body for you with --print-query.

03207 · partial

Handle the line that will not parse

A line that does not match its declared format is not dropped and does not fail the batch. It comes back in unparsed with the reason and the raw text, and every other record is still written.

POST/v1/parse?strict=false 207 · 1 unparsed
E_FORMAT_UNPARSED
line 3: 2026-11-08 09:13:59 WARN checkout-api slow

reason — slow is a bare token, not a key=value pair. logfmt needs a value on every field.

The record is kept with the fields that did parse, and unparsed[0].raw holds the original line for a retry.

const batch = await client.parse(file, { strict: false });

for (const line of batch.unparsed) {
  console.warn(line.index, line.reason, line.raw);
  deadLetter.push(line.raw);
}
batch = client.parse(file, strict=False)

for line in batch.unparsed:
    log.warning("%s %s", line.index, line.reason)
    dead_letter.append(line.raw)

unparsed[] is capped at 100 entries per batch

Set strict=true only when a partial batch is worse than no batch — it returns 422 and writes nothing.

05integration

Thirty minutes, three steps

  1. 01

    Create a project key

    One key per project, scoped to one pipeline. Put it in the environment, never in the repo — the SDK reads PAYLOADDECK_KEY on its own.

  2. 02

    Send one real file

    Not a fixture. Take 1,000 lines from the service that hurts most and read the record shape it comes back as. Keep unparsed open in a second pane.

  3. 03

    Point one rule at it

    Start with level = "error" and duration_ms > 5000. One rule that fires on real traffic beats a dashboard nobody opens.

06schema

Response fields

Every record carries these fields. Anything your log line contained and PayloadDeck could type lands in record as a flat key — no dotted paths, no nested objects to unwrap.

record object · /v1/parse
fieldtypenotes
idstringStable per record. Use it to dedupe a replayed batch.
received_attimestampServer clock, ISO 8601 with milliseconds, UTC.
formatenumDetected from the first 20 lines: logfmt, json, syslog, regex.
recordobjectOne flat object per line. Keys keep the casing of the source line.
record.levelenumdebug info warn error fatal. Unknown levels fall back to info.
record.tstimestampRead from the line. Falls back to received_at when the line carries no time.
record.duration_msnumberPresent only when the line carries a duration in a unit PayloadDeck can convert.
unparsedarrayEmpty when every line parsed. Each entry has index, reason, raw.

That is the whole response. If a field is missing, the line did not carry it — nothing is filled in for you.
