# AnnualDesk 企业服务核对单：发现与取舍

## 一 交付范围

单文件静态页，CSS 与 JS 内联，零外部请求。三档演示价（工商年报 ¥680、年报加急 ¥980、注销代办 ¥1,280），演示付款，不接真实查企、支付与材料收集。示例企业名与 18 位统一社会信用代码均为合成值。

## 二 六步里真正跑过的部分

第 1 到 3 步按指南读需求、读规范、记账，取值记录见同目录 DECISIONS。第 4 步写完页面后，第 5、6 步的读数全部来自浏览器实测，没有估算。

## 三 版式取舍

选 Service Document（单据式）：左侧摘要联带撕口，右侧正文按 01 核对、02 选服务、03 费用与付款、04 回执排，抬头是核对单而不是大标语。

淘汰三种骨架：Stat-Led 是上一版的骨架，但这一页没有真实统计口径，一个巨大数字只会是装饰；Workbench 会把交易页做成后台表单，与「一张单子」相反；Narrative Workflow 适合营销时间线，这里的阶段是交互步骤，不是叙事。

记忆点三样：摘要联的撕口、付款后的「演示」章、受理单号。三者都不靠插画和图标堆出来。

## 五 对比度实测

注入去掉动效的样式后逐节点扫，107 个文本节点，最低 5.75:1，没有低于 4.5:1 的正文：

| 组合 | 实测 |
| --- | --- |
| 正文 90% 黑 / 白底 | 17.4:1 |
| 次级 60% 黑 / 白底 | 5.74:1 |
| 次级 60% 黑 / 灰底 | 5.17:1 |
| 强调字 / 强调浅底 | 5.75:1 |
| 白字 / 强调色 | 6.38:1 |
| 错误字 / 错误浅底 | 8.38:1 |
| 告警字 / 告警浅底 | 6.08:1 |
| 成功字 / 成功浅底 | 5.88:1 |

第一轮扫出两处 1.36:1 的元信息分隔点，是 `#dddddd` 的小圆点当文本节点读了；已把分隔点改成次级文字色。输入框边框从 Gray4 提到 Gray7（白底 3.41:1），悬停边框从 40% 黑提到 60% 黑，圆环边框同改，控件边界都过 3:1。

## 六 核心交互实测

1. 空提交：`#name-err` 出「请填企业名称」，`#code-err` 出「请填统一社会信用代码」，两个输入都写 `aria-invalid="true"`，焦点留在名称框。
2. 格式错：代码填 `abc`，只出 `#code-err`「统一社会信用代码是 18 位数字或大写字母」，名称提示不被覆盖。
3. 示例：填入合成企业名与 18 位码，长度、`^[0-9A-Z]{18}$`、前缀与后缀逐项核对通过。
4. 查询：按钮禁用并进 900ms 加载态；结果出登记信息、经营提示与三档服务；状态标签从「待核对」变「已核对」。
5. 选方案：三档切换，费用区合计、摘要联合计、弹层金额三处同源；价格数字有一次 200ms 跳数。
6. 付款：未核对时按钮禁用并给提示；打开弹层后焦点在取消；确认按钮进 900ms 加载态，写「付款处理中」。
7. 回执：生成 `AD` 加年月加四位序号的单号；摘要联同步；焦点移到回执标题；页面滚到回执；盖章动画 240ms。
8. 重置：清空输入、方案、金额、状态、单号与回执，解锁表单，焦点回名称框。
9. 付款后锁定：输入、示例、查询、三档单选全部禁用，防止回执与再次查询打架；重置后全部解锁。

键盘：Tab 顺序为跳过链接、品牌、返回条目、名称、代码、示例、查询、单选组、付款、须知条目。单选组只占一个 Tab 位，组内用方向键切换并即时更新合计。弹层内 Tab 在取消与确认之间循环，两个按钮都可聚焦；Esc 关闭后焦点回到付款按钮。

## 七 状态与无障碍

- 1280 与 375 两档各 0 个小于 24px 的触控目标；移动端文字链接高 44px。
- 所有输入都有可见标签；错误提示用 `aria-describedby` 关联；状态标签有 `aria-live`。
- 页面只有一枚 H1；提示条、方案行、回执、须知都按区块标题组织。
- `prefers-reduced-motion: reduce` 下所有动画与过渡压到 0.01ms，弹层直接开关。
- 焦点环 2px 强调色加 2px 偏移，键盘态实测在方案行、输入框、按钮上都可见。

## 八 缺口与遗留

1. TDesign 的间距原文只有 8 基数与 4、12 两档，页面用到的 32 与 48 按 8 的倍数派生；控件高 40px、圆角 4 / 8px、内容宽 1160px、摘要列 208px、弹层 440px 原文都没有，成套派生并记在 DECISIONS。
2. 输入框组件篇只说大中小三档，没有 px；40px 高是按大档派生，未与官方组件实测对账。
3. 12px 文本占 25%，符合 TDesign 桌面最小字号，但说明文字多；再压缩会把表注挤成 12px 以下，没有这么做。
4. 需求只给演示价与演示边界，没给时效口径、经营异常的具体分支、回执类型与退款条件；页面按「演示」统一收口，没有编造真实时效。
5. 真实查企、支付、材料上传都没有接；演示页不产生真实回执、不扣款。

## 九 必选场景检验：形状一致

本站的容器件（摘要联、方案行、回执、弹层、须知条目）统一 8px 小圆角，动作件（按钮、文字链接、状态标签）统一 4px 圆角或胶囊；输入框按控件档 4px。悬停、选中、按下只换填充与文字色，不出现下划线、方框或左侧竖条。选中的方案行用浅强调底加 4px 左侧色条，这是选中态的位置指示，不是形状语言改变。同排的查询按钮与示例链接热区都取 40px（移动端 44px），基线对齐；示例链接的可视文字只有 14px 一行，不另加容器形状。
