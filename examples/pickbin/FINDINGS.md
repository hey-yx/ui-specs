# FINDINGS · PickBin（pickbin）

## 1. 本稿相对合格线的落点

以下全部为浏览器实测（Chrome / CDP，`file://` 直开，1280×900 与 320/375/768 四档）。

| 合格线 | 实测 | 结论 |
| --- | --- | --- |
| 四档无横向溢出 | 320 → 305/305、375 → 360/360、768 → 753/753、1280 → 1265/1265 | 达成，四档另查元素级越界 0 个 |
| 零外部请求 | `performance.getEntriesByType('resource').length` = 0（四档） | 达成 |
| 行高 = 字号 + 8，违例 0 | 初始态 79–80 个文本节点 0 违例；成功态 83 个节点 0 违例 | 达成 |
| 正文对比度 ≥ 4.5 | 正文 17.49:1；次要文字 5.74:1（白）/5.58:1（灰） | 达成，最低文本项 4.50:1（成功绿字） |
| 非文本 ≥ 3 | 输入框边框 3.41:1；拖放区虚线 3.07:1；焦点环 6.54:1 | 达成 |
| 强调色面积 < 5% | 0.52%（1280 初始）、0.58%（成功态）、0.72%（768）、1.80%（375）、1.59%（320） | 达成 |
| 核心交互真跑 | 选文件、投柜进度、复制、取件四态校验、下载递减、拖放、再来一次，共 8 条路径 | 达成，前后数字见 DECISIONS 第 8 节 |
| 键盘可完整操作 | Tab 顺序：跳过链接 → 品牌 → 2 锚点 → 拖放区 → 2 组 radio → 主按钮 → 取件码输入 → 取件；焦点环 `solid 2px / offset 2px` | 达成（原生文件对话框未在无头环境点开，见第 4 节） |
| 减少动效 | `prefers-reduced-motion: reduce` 下过渡 200ms → `1e-05s` | 达成 |

两条"照字面执行就会出错"的地方，处理如下：

1. **hover 的 blue-6 不达 AA。** TDesign 语义 token 把 hover 映射到 blue-6（`color/tdesign.tencent.com--color.md:508`），实测白字 **4.47:1**。按 `guide.md:43` 的"token 映射出的 hover 同样按实际底色复算"换 blue-8（9.40:1）。如果照抄 token 名而不复算，这一处就会带着 4.47 上线。
2. **成功绿刚好卡线。** green-6 在白底是 **4.50:1**，正好等于 4.5，四舍五入前的原始值若略有偏差就会掉到线下。它只用于 14px 的短提示，不再往上叠第二层底色。

## 3. 新缺口（指南没有、被迫派生的维度）

以下五项是本稿在做的时候撞到的空白，库内没有对应原文，值得回填。

1. **进度条几何。** 库有"加载要有进行中反馈"（`patterns-loading` 的选择选用标准），但没有确定型进度条的规格：条高、圆角、槽色、百分比文字位置、`aria-valuenow` 更新节奏。本稿自定 4px 高、2px 圆角、gray-3 槽、brand 填充、每帧同步 `aria-valuenow`。**建议回填**到 `patterns-loading` 的数值层。
2. **瞬时提示的停留时长。** 动效篇只规定"动多久"（200/240/280ms），没有规定"提示停留多久"。复制成功的"已复制"本稿取 2400ms。**建议回填**一档 2000–3000ms 的值，否则每个项目会各写一个数。
3. **拖放区的三态规格。** `components/govuk--file-upload.md:197-199` 只说"更大、常显、对交互有反应"，没有给边框样式、拖入态配色、拒绝态表现。本稿自定：灰底 + 1px 虚线 + gray-7（3.07:1）、拖入时换 brand 边 + blue-1 底。**建议回填**，这是上传类页面的必经控件。
4. **同一语义色的"文字档 / 线条档"分层规则。** 原文给的是单值加一句自述对比度（如 red-6 4.32:1），没有"语义色在文字与非文本上应取不同档"的成文规则。本稿被迫自己分成 red-7（文字）/ red-6（线条）。**建议回填**：语义色的两档映射表可以一次性解决所有项目的错误色问题。
5. **元素级溢出检查口径。** 指南的四档验收只写 `documentElement.scrollWidth === clientWidth`，这是文档级判断；本稿另加了"任一元素 `right > clientWidth` 或 `left < 0`"的元素级扫描（四档均 0）。**建议回填**，因为文档级不溢出仍可能有元素被裁。

## 4. 已知局限

1. **上传与下载是模拟，不是传输。** 进度由定时器推进（投柜 9 帧 × 110ms ≈ 1.04s，下载 5 帧 × 90ms ≈ 0.46s），不读取真实字节，也没有分片、断点、失败重试。2GB 上限只做 `File.size` 判断。
2. **取件码存在内存里，刷新即丢。** `vault` 是页面内的对象；预置的 `8F3K2P`（"2026-第三季度报价单.pdf"，剩 2 次）是硬编码演示数据，不是任何真实文件。页面用横幅、限制表和页脚三处声明了这一点。
3. **原生文件选择框未由真人点开。** 无头环境无法操作系统对话框，文件是通过 CDP `DOM.setFileInputFiles` 注入真实文件（357,000B 的 PDF）触发 `change`，拖放用合成 `DataTransfer` 触发 `drop`。两条路径都进入应用自身的处理函数，但"鼠标点按钮 → 系统对话框 → 选文件"这一段没有走。
4. **剪贴板只验证到提示。** 实测"已复制"出现，但没有读回剪贴板内容做字符串比对；`execCommand` 路径依赖用户手势，脚本里点与真人点在边界情况下可能不同。
5. **屏幕阅读器未实听。** 只检查了 `label`/`aria-describedby`/`aria-invalid`/`aria-live`/`aria-current` 等属性与 DOM 结构，没有用 VoiceOver/NVDA 走一遍朗读顺序。
6. **单一浏览器。** 只在 Chrome 实测。`:has()`（选中态边框）、`text-wrap: balance/pretty`（标题与说明断行）在旧版 Safari/Firefox 上会退化为普通换行，未实测退化后的观感。
7. **中文断行没有分词。** 靠行长 34em + `text-wrap` 控制，极端窄屏（320）仍可能把"取件码""到期"这类词拆到两行；`line-break: strict` 只能管标点，管不了词。
8. **未测缩放与强制高对比。** 只测了 320/375/768/1280 四档固定宽度，没做 200% 缩放、400% 重排，也没测 `forced-colors: active`（Windows 高对比模式）下的表现；焦点环与选中态边框在这种模式下可能失效。
9. **颜色只按 sRGB 算。** 未在 P3 广色域屏上看实际观感，也未验证系统级"增加对比度"设置被浏览器二次调整后的效果。
