# FINDINGS · 用 UISpecs 做「PickBin」的摩擦记录

记录原则：只写基准规范给不了、只能从别处取或自己派生的地方，每条带路径；数值类问题优先写，因为它直接影响「照规范取值」的可靠性。

## 一、TDesign 没给的量

1. **间距只有基准，没有完整档位。** `content/layout/tdesign.tencent.com--layout.md:78` 给 8px 基准，`:138` 补 4 与 12 两档，`:92` 的槽是 16，`:96` 的安全边距是 24。本站最终用 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96，32 以上标「8 的倍数派生」。问题不在 8px 基准，而在档位要自己拼：换个 AI 可能拼出 4 / 8 / 16 / 24 / 40 / 64，站与站对不齐。建议补一张 spacing scale，或明确「未列档位按 8 的倍数派生」。

2. **圆角没有像素。** `content/components/tdesign.tencent.com--button.md:64` 只写「矩形、方型、圆角矩形、圆形」四种形状，没有 radius；radio 与 input 的组件文章也没有给出可引用的像素。本站按钮与面板用 8，单选卡与输入框用 4，全标 derived。代价是「同形状语言」能自证，但无法声称这些像素来自 TDesign。

3. **44×44 目标尺寸不在 TDesign 两篇里。** 按钮与输入框最小高度取 WCAG 2.5.5 的 44 by 44（`content/a11y/w3c--wcag-2.2.md:871`）。这是跨源下限，不是 TDesign 组件尺寸；如果只读 TDesign，会得到「按组件默认高度」而不是「按可点下限」。本站所有主按钮、次按钮、输入框、柜口按钮都按 44 高做，视觉上比 TDesign 常见 40 高一档。

4. **TDesign 的动效文章没有减弱动效规则。** 200 / 240 / 280ms 三档和三条曲线在 `content/motion/tdesign.tencent.com--motion.md:101-103`、`:115-117`，但 `prefers-reduced-motion` 的兜底不在里面；本站按 `content/motion/ui-specs--motion-implementation.md:90` 把过渡压到 0.01ms，并把滚动改 auto。只用 TDesign 会漏掉这类系统偏好。

5. **默认错误红不能直接当小字。** `content/color/tdesign.tencent.com--color.md:52` 的 Red6 `#d54941` 原文自己标了「对比度 4.32:1」，低于正文 4.5；本站错误图标与输入边框仍用它（非文本 3:1 够），错误文案换 Red8 `#ad352f`（`:60`），错误横幅底用 Red1 `#fff0ed`（`:54`）。这不是调色偏好，是同一色相里按用途拆档；规范应把「文字用 Red8、填充用 Red6、浅底用 Red1」写成一句。

6. **焦点环只有原则，没有尺寸。** WCAG 2.4.7 要求键盘焦点可见，但 2px 线宽与 2px 偏移是本项目自定；TDesign 的按钮文章没有 focus ring 的像素。本站用 2px `--accent` + 2px offset，键盘可见、鼠标点击不出现，标 derived。

7. **「柜体」不是组件，是内容插图。** TDesign 的 icon 文章给的是线性图标体系，没有柜体、柜门、凭条这类产品插图；本站用 440×340 的内联 SVG 手绘柜体，柜口热点叠 HTML。这样做满足了「产品证据真画、零外部请求」，但也意味着插图不参与设计系统的数值对账，只能按色彩与间距规范靠拢。

8. **320 首屏放不下完整柜体。** 320×568 下标题两行、说明四行、主按钮 44 高之后，柜体从 y=465 开始，首屏只能露出柜口上半；主按钮完整，柜口标题可见，柜口按钮在首屏下沿外。这是窄屏高度的物理限制，不是溢出；验收时把「主按钮完整」和「柜体完整」分开看，不要用一个「首屏完整」概括。

## 二、流程与验证

9. **程序化焦点要自己补。** 切到第 02 步后把焦点放到阶段标题，需要标题带 `tabindex="-1"`，并在 CSS 里去掉 `:focus` 的 outline；添加文件后把焦点从消失的空状态按钮移到「文件」标题，也要同样的处理。库的组件文章讲焦点回输入框，但没讲「阶段切换后的标题焦点」这类页面级规则；本站已在 `setStep` / `scrollToSection` 与 `addFiles` 里实现。

10. **复制 API 依赖安全上下文。** `navigator.clipboard` 只在 secure context 可用；直接双击 `file://` 打开时走 `document.execCommand('copy')` 兜底，失败再选中码让用户手抄。案例站最终通过 http 提供，复制走 Clipboard API；本地单文件打开时不能把「系统剪贴板里一定有」当成已验证。

## 结论

这站的摩擦集中在三处：**TDesign 的间距、圆角、焦点环没有可直接引用的像素**；**功能色的默认红与 44 目标尺寸要从别处补**；**窄屏首屏与程序化焦点是页面级问题，组件文章管不到**。前两类建议补进 guide 的「基准规范缺口与派生」索引，第三类留给每站的自查表。
