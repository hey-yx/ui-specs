# FINDINGS · 用 UISpecs 做「EpDeck」的摩擦记录

记录原则：只写「库/规范给不了、只能绕」的地方，每条带原文路径或行号。数值类问题会直接影响「照规范取值」的可靠性，优先级最高。

---

## 一、TDesign 两篇覆盖不到的量

1. **没有间距体系。** `content/type/tdesign.tencent.com--fonts.md` 只给字阶与行高，没有任何 spacing scale；`content/color/tdesign.tencent.com--color.md` 也没有。我只能把字阶步进 `+2/+4/+8/+12/+16`（`fonts.md:44-46`）当粒度，组合出 4/8/12/16/24/32/48/64/96。问题：同为「按原文取值」，两个 AI 可以组合出两套不同间距，站与站之间无法对齐。建议库补一篇间距/栅格规范，或在 TDesign 分区标注「本篇无间距，取别源」。

2. **动效完全缺失。** 两篇没有 duration、easing、reduced-motion 的任何规定。本站的 200ms / 240ms 两档来自需求书 `requirements.md:29`（200-250ms），缓动 `cubic-bezier(.22,.61,.36,1)` 是我自定的。这两类值在 DECISIONS 里无法标 TDesign 行号，只能标「需求书 + 自定」。

3. **没有圆角规范。** 两篇都没有 radius 值。为不编数值，整站用直角（0），只保留圆形（播放键、状态点）这类几何形状。代价是「影院感」少了一点圆润，但至少每个数值都能交代出处。

4. **发丝线只有颜色没有宽度。** 分隔线用 `#393939`（Gray11，`color.md:208-209`），1px 这个宽度来自需求书措辞（`requirements.md:26`「1px 发丝线」），不是 TDesign 原文。另：`#393939` 在 `#181818` 上只有 1.54:1，作为装饰分隔线可以，作为控件边界不达标，控件边界我另取了 `#777777`（3.97:1，`color.md:202-203`）。

5. **数字字体不可用。** `fonts.md:35-39` 推荐 TCloud Number 做等距数字，但文章只给了字符示意，没有字体文件、没有 web 分发方式。零外部请求的约束下只能用 `font-variant-numeric: tabular-nums` 近似。规范里「用腾讯云数字字体」这句对单文件页面是不可执行的。

6. **暗色字阶的 35% 档不达标。** `fonts.md:89` 写「文字显示色彩对比满足至少 1:4.5」，但实测 `#ffffff 35%` 在 `#181818` 上是 **3.23:1**，`55%` 是 6.08:1。也就是说 Wh3/Wh4 只能用于禁用与装饰。这条落差会直接坑到「照档位用色」的人：必须按实际背景复算，不能信档位自述。

7. **「扩展色橙系」在原文里不存在。** `color.md:355-489` 的扩展色只有 Cyan / Purple / Yellow / Pink 四组；橙、红、绿在「功能色」区（`color.md:36-181`），Orange5 的定义还是「告警色」（`color.md:114`）。任务书按「扩展色橙系（:114-115 附近）」指路，实际行号落在功能色区。对 AI 来说缺一份「色相 → 分区」索引，容易被「扩展色」三个字带偏。

## 二、版型与组件原型的问题

8. **video-first-hero 假设有视频资产。** `content/layouts/layout--video-first-hero.md:53` 的区块 1 是「Hero with video background」，`:62-63` 还要求自动播放、字幕、暂停控件、reduced-motion 用静态海报。单文件零外部请求拿不到视频，只能降级成内联 SVG 静帧：版型语义从「视频优先」变成「大图优先」。版型库缺「无视频资产时怎么降级」的说明。

9. **原型 CTA 位置与内容型产品冲突。** 同文件 `:60` 写 CTA 在「Overlay on video (center/bottom) + Bottom section」。追剧站的卡片本身就是内容入口，overlay 里再堆两个 CTA 会挤压剧名。本站保留「继续观看 + 加入追剧单」两个 overlay CTA，底部不再重复 CTA，改用 Ft5 收束句。原型是落地页语汇，直接套内容站需要改写。

10. **N1b 默认带下拉，但测试口径要求入口必须真跑。** Hallmark `references/components/n1b-saas-three-section.md` 的示例含 hover 下拉（Product → Gateway）。本站只有「首页/剧集/电影/综艺」四个入口，全部要真实过滤片库；做下拉只会得到假交互。我去掉了下拉，把入口做成筛选。组件原型与「每个交互都要点得通」的验收口径需要显式说明优先级。

11. **Ecosystem Index 的「多人/作者」面没内容可放。** `references/macrostructures/20-ecosystem-index.md` 的典型面是 featured / latest / by category / by people。追剧站没有创作者维度，只能换成「主推 / 热播 / 热榜 / 猜你喜欢」。宏观结构可迁移，但四条发现面要按产品重写。

## 三、内容与验证

12. **库只给数值，不给内容。** 12 部剧、演员、97 条分集简介全部原创，否则页面是空壳。这对「数值可信度」没有影响，但对「真实文案」验收有影响：评审需要知道哪些是产品内容、哪些是规范取值。

13. **headless 环境的定时器节流。** `setTimeout(240ms)` 的骨架屏在自动化浏览器里可能 1s 后才落地，交互脚本必须等 ≥1.5s 再断言，否则会误判「筛选后 0 张卡」。真实浏览器无此问题；记录在此避免下一轮误判为 bug。

14. **12 张封面全部内联 SVG，实测外部请求 0、`<img>` 0。** 每张封面 2 段渐变 + 12-34 个图元，构图各异（灯塔 / 窗格 / 宫檐 / 墨山 / 店面 / 楼体 / 行星 / 波纹 / 麦克风 / 餐盘 / 声波 / 雪林）。这套做法可复用，但成本是单文件 ~69KB，如果库要求「精修图形」成为常态，需要接受体积上涨。

---

## 结论

本轮真正卡住的不是「找不到数值」，而是三类缺口：**间距/动效/圆角这类非字体色彩规范没有收录**、**规范自述与实测不一致（暗色 35% 字阶）**、**原型文件默认有外部资产（视频）而测试口径要求零请求**。前两类建议在库内补一篇「TDesign 未覆盖项」索引，第三类建议在 layouts 分区加降级说明。
