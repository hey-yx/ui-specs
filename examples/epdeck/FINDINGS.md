# FINDINGS · EpDeck（epdeck）

## 1. 本稿相对合格线的落点

全部是浏览器实测值（`file://` 打开，CDP 设备模拟），不是估算。

| 合格线 | 本稿实测 |
| --- | --- |
| 四档无横向溢出 | 320 = 320/320、375 = 375/375、768 = 753/753、1280 = 1265/1265；首页与详情都量过，无例外 |
| 零外部请求 | `performance.getEntriesByType('resource').length` 四档均为 0；字体为系统栈，图标为内联 SVG，封面为 CSS 渐变 |
| 行高 = 字号 + 8 | 首页 209 个含直接文本的节点、详情 93 个节点，违例 0（容差 0.6px） |
| 正文对比度 ≥ 4.5 | 正文 7.01；次要文字 7.01；封面说明 4.95（全站最低的正文字号文本）；按钮文字 6.22 |
| 非文本 ≥ 3 | 控件边界 3.97 / 3.46；焦点环 5.51；选中描边 4.23 |
| 强调色实填 < 5% | 320 = 2.70%、375 = 2.30%、768 = 1.15%、1280 = 0.68% |
| 交互有响应、数字对得上 | 18 项交互逐项真点，前后值见 DECISIONS 第 8 节；控制台 0 条未捕获报错 |
| 键盘可用 | skip link 是第一个可聚焦元素；三处抽屉焦点锁在面板内（4 个元素内循环）、Esc 关闭、焦点还原；返回首页后焦点回到来源卡片 |
| 尊重减少动效 | 模拟 `prefers-reduced-motion: reduce` 后，抽屉 0.28s → 0.001s，按钮 0.2s → 0.001s |

没有做到「有真实剧照」这一层：全站零外链的前提下，封面只能是色板渐变 + 型排巨大字。

## 4. 已知局限

1. **数据是虚构的。** 12 部剧、评分、播放量、追剧人数都是编的，页脚已写明「演示站点，剧集、评分与播放数据均为虚构」。不编造真实作品与真实指标。
2. **没有片源。** 播放器是界面模拟：本地计时推进进度，不加载任何视频，页面上也写明了。没有登录、支付、收藏后端，「追剧」只存在内存里，刷新即还原为 3 部。
3. **封面不是剧照。** 零外链约束下用色板渐变 + 型排字构成，能读，但不能替代真实剧照；这也是本稿与真实视频站差距最大的一处。
4. **未测的状态。** 页面没有表单，所以「表单校验三态」不适用（搜索是即时筛选，只有有结果 / 空态两态）；没有网络请求，所以没有加载态与骨架屏——不做假骨架去凑清单。悬停、按下、焦点、禁用、空态、内容超长换行都真实出现过并检查过。
5. **只有深色一套。** 基准规范有明暗两套，本稿只落了深色（受众在夜间使用）。切浅色需要另一套中性色与文字透明度，未验证。
6. **字号档位偏多。** 实际用了 12 / 14 / 16 / 24 / 28 / 36 / 48 七档，另加封面装饰 64 一档。NN/g 的「最多 3 档」说的是层级数，本稿层级仍是三档（标题 / 副标 / 正文）+ 展示档 + 辅助档；但档位总数确实超出，若后续扩展页面，建议把 24 与 36 分别收进 28 与 48。
7. **只在 Chromium 实测。** Safari（滚动条宽度、`overflow-x: clip`、`aspect-ratio`）和 Firefox 未跑；768 / 1280 两档的 15px 差值就是滚动条占位。
8. **`select` 的行高由浏览器决定。** 作者写在 `select` 上的 `line-height` 被 Chromium 忽略（实测 `normal`），其 `option` 计算值为 12 + 8 = 20px。这是平台行为，不是遗漏；若必须控制，只能自绘下拉。
9. **320 档封面偏窄。** 两列布局下单卡 136px，剧名超过 6 字会折两行；封面上的评分徽标与更新信息在小屏仍可读（12px / 4.95:1），但信息密度接近上限。
10. **标签标题里的马头 emoji 与本页无关。** 测试环境把 `document.title` 前缀替换成了 `🐴`，源文件 `<title>` 里没有这个字符，交付时以文件为准。
