## 3 新缺口（建议回填 guide 的「基准规范缺口与派生」）

**3.1 品牌深色不能直接做深底上的按钮底**

`#7137bf` 压在 `#181818` 上实测 **2.56:1**，低于 WCAG 2.2 非文本对比的 3:1。深色区的主按钮要么反向取同族浅档（本次 `#c69cff` + `#3b007b`），要么加一圈浅色描边把边界做出来。建议在「色阶当文字」条后面补一句：**色值同时是控件边界时，换底色后要重算边界对比，不只算文字**。

**3.2 语义错误色本身不达 AA**

`#d54941` 是 TDesign 自述的错误色（`content/color/tdesign.tencent.com--color.md:80`），压白 **4.32:1**，直接当错误文字不达 4.5。本次错误文字取 Red7 `#ad352f`（6.31:1），Red6 只做边框。建议把这条并进「色阶当文字」的既有例子。

**3.3 TDesign 中性色自述「常用文字对比度均大于 4.5」不成立**

`content/color/tdesign.tencent.com--color.md:180` 这么写，实测：`#777777`（Gray8，`:203`）压白 **4.48:1**，差 0.02；`#c6c6c6`（Gray5，`:197`）压白 1.71，作控件边界远不达 3:1。建议把这颗具体数值补进 guide 的同一条，省得每个项目重算。

**3.4 字阶封顶 64px 与「大字占满折叠线」的版式冲突**

Marquee Hero 要 8 到 14vw（1280 宽即 102 到 179px），TDesign 第二字阶封顶 64px（`fonts.md:60`）。两者不能同时满足。本次取 64px，用三行、行间分布与满宽发丝线补占位感；代价是视口高过 1100px 时行间留白会更大。建议在 guide 的版式条目里写明：**版式要求与基准规范字阶冲突时，以基准规范为准，并写下补占位的做法**。

**3.5 CSS 让位别用 margin 配 `width:100%`**

正文列用 `margin-inline-start` 让出编号栏时，`inline-size:100%` 的子元素（表格）会把 margin 加在 100% 之外，1280 档实测 `scrollWidth 1304 > clientWidth 1265`。正确做法是把让位做成父级的 `padding-inline-start`，标题再负 margin 拉回。这是工程坑，不进规范，记在这里防下次重踩。

## 4 已知局限

**4.1 首屏的空是 64px 上限换来的**
见 3.4。三行 64px 在 1280 档占不满折叠线的垂直空间，靠 `space-between` 与满宽发丝线补。这是「遵守数值纪律」与「版式原件」之间的取舍，不是排版失误。

**4.2 纸张演示是重绘，不是产品**
文档区与讨论栏全部由 HTML + CSS 拼成，没有截图、没有假浏览器外框。优点是零请求、可缩放、文字可选中；代价是它只能证明结构，不能证明真实产品的完成度。

**4.3 无 JS 时只剩静态页**
问答靠原生 `<details>` 可开合、导航锚点可用；但徽标定位、只看未解决、标为已解决、任务勾选、计费切换、试用弹层全部失效，页面停在「2 处未解决 / 月付 / 未完成」的初始态。属于营销页可接受的降级，没做 `<noscript>` 提示。

**4.4 只在 Chromium 里验过**
四档、断点边界、行高、对比度、键盘、交互全部在 Chromium 实测。`backdrop-filter` 写了 `-webkit-` 前缀，没在 Safari 真机验证；`color-mix()` 用在导航底，Safari 16.2 以下失效，降级结果是胶囊变不透明白底，不影响可读性。

**4.5 对比度是算出来的，不是取色器采的**
脚本沿祖先链合成背景色后用 WCAG 相对亮度公式计算，覆盖了半透明导航底与深色区；但算的是 CSS 声明值，没有对截图做像素采样。

**4.6 12px 已经到 27.6%**
接近三成上限。再往上加辅助标签就会越线；要降只能把作者名、行号这类字段删掉或放大，前者丢信息，后者会让文档区失去「真实界面」的比例感。判断 27.6% 是这一版该停的位置。

**4.7 空态文案与数据绑死**
空态写的是「3 处讨论都已解决」，按这一版的 3 条讨论写死。讨论条数变了要同步改文案，页面没有做复数拼接。

**4.8 滚动状态在隐藏标签页里量不到**
`browser_exec` 的标签页 `document.hidden === true`，滚动事件会被节流、`requestAnimationFrame` 不回调。验证导航激活态时用 `window.scrollTo` 加 `dispatchEvent(new Event('scroll'))` 手动触发，并等 1 至 2 秒（隐藏页的 `setTimeout` 最小 1 秒）。这也是导航里 `queue()` 在 `document.hidden` 时退回 `setTimeout` 的原因。
