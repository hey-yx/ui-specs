## 1. 本稿相对合格线的落点

可核验事实，不含形容词。

| 项 | 实测 | 测法 |
| --- | --- | --- |
| 四档横向溢出 | 320 → 320/320；375 → 375/375；768 → 753/753；1280 → 1265/1265 | `documentElement.scrollWidth === clientWidth`（后两档 clientWidth 已扣 15px 滚动条） |

| 行高 | 177 个含直接文本的节点，违例 0 | 逐节点比 `lineHeight` 与 `fontSize + 8`，容差 0.6px |
| 字号档位 | 每档断点恰好 3 个字号：320 {28,20,16}；375 {36,24,16}；768 {48,28,16}；1280 {64,28,16} | 同上普查顺带统计 `fontSize` 分布 |

| 正文对比度 | 最低 5.74:1（次要文字 `rgba(0,0,0,.6)` 压白底） | WCAG 相对亮度公式，半透明字色按底色合成 |

## 3. 新缺口（指南没有、被迫派生）

按影响排序；每条都写了建议。

1. **营销页的占位素材与「不许假证言」规则冲突。**
   需求里要求客户 logo 与用户评价（`briefs/samepaper.md:13`），而库规则明确「假证言、假 logo 墙、假指标数字都不放」（`content/patterns/ui-specs--test-walkthrough.md:22`）。
   处理：保留区块，标题旁标「示例数据」，logo 下加一行「客户名、评价与人数都是本稿的虚构占位，上线前换成真实素材」，页脚再声明一次。
   **建议回填**：指南加一条「营销页占位素材」规则——允许虚构产品名与价格（已有），客户/证言必须带可见标注，或改成「待填」空位。

2. **阴影 / elevation 无源。**
   基准规范给颜色与边框，不给阴影数值；缺口表里也没有阴影一行。本稿干脆不用阴影，靠 1px 边框 + 灰底区分层叠。代价：弹窗与页面的分离度弱于带阴影的方案（实测遮罩 0.45 黑仍能拉开层级，但卡片之间只能靠边框）。
   **建议回填**：「无阴影时用什么表达层叠」或直接给 4 档 elevation 值。

3. **窄屏大标题降档没有规则。**
   320px 宽、左右各 16px 后版面 288px，9 个 36px 汉字放不下，浏览器把「任务」拆开、末行只剩「上」。
   处理：加 359px 断点，H1 退到 28px、H2 退到 20px，仍是基准规范字阶内的值。
   **建议回填**：「大标题在最小断点的降档规则（保持每屏 3 档）」。

4. **分段控件（计费周期切换）没有基准规范组件规范。**
   TDesign 库内抽了色/字/布局/图标/动效，没有抽 Tabs 或 Radio 的视觉规格。本稿派生：整体 44px 高、容器 1px `#8b8b8b` 边框、选中项品牌浅底 + 1px 内描边、选中文字 8.52:1。
   **建议回填**：一段「两选一/多选一的分段控件」最小规格（尺寸、选中态表达、对比度下限）。

5. **示意界面（假 UI）的可访问性处理没有规则。**
   首屏那张「纸面」是画出来的界面，里面有文档名、评论、任务。若按普通 DOM 暴露，屏读会读到一堆不存在的控件。
   处理：整块 `role="img"` + 一句 `aria-label` 概述，「转为任务」按钮用 `aria-hidden` 的 span 假装，不进 Tab 序。
   **建议回填**：「营销页示意 UI 用 role=img 包一层，内部不承载真实控件」。

6. **价格文案的「省多少」表述没有规则。**
   第一版写「换年付可省 20%：¥93.60 / 人 / 年」，评审读成「年付价 ¥93.60」。改成「月付 ¥39.00…换年付 ¥31.20，每年省 ¥93.60」后歧义消失。
   **建议回填**：「折扣文案必须同时给出原价、折后价、节省额三个数」。

## 4. 已知局限

- **只测了 Chrome**（通过 CDP 驱动）。Safari 与 Firefox 未测；`<dialog>` 在 Safari 15.4 以下不可用，`@starting-style` 与 `transition-behavior: allow-discrete` 在旧版会退化成「直接出现」，不影响可用性但会丢动效。
- **单页交付**：页脚里 9 个链接没有真实目标页，点了给一条轻提示（`role="status"`），不是真实跳转。这是演示稿的边界，不是遗漏。
- **数据全为虚构**：客户名、评价、人数、价格都是示例，页面上有可见标注；没有真实指标数字。
- **没有屏幕阅读器实测**：只做了语义结构、`aria-*`、键盘顺序的检查，没有跑 VoiceOver / NVDA 实际朗读，无法确认朗读顺序是否完全符合预期。
- **没有性能数据**：只确认零外部请求，没有测 LCP / CLS / 长任务。单文件约 50KB，预期不差，但没有实测数字，不写结论。
- **只测四个宽度**：320 / 375 / 768 / 1280。没有测 200% 页面缩放、系统字体放大、超长中英文混排（例如 60 字符的团队名）下的换行。城市名/团队名输入框在极端长文本下会正常换行，但没有专门构造用例。
- **320 档层级压缩**：H1 28px 与 H2 20px 只差一档，视觉层级比大屏弱；这是为「不拆词、不孤字」付的代价，已记在回炉记录 c。
- **动效只做了状态反馈**：没有滚动进场、视差、装饰性动画。TDesign 原文明确不建议首次载入做顺序动画（`content/motion/tdesign.tencent.com--motion.md:146`），本稿遵守，但也意味着页面偏静。
