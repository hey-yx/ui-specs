# SamePaper · 发现

## 1. 合格线落点

| 项 | 判断依据 | 实测 |
| --- | --- | --- |
| 四档无横向溢出 | `scrollWidth === clientWidth` | 320 / 375 / 768 / 1280 四档相等；另加 414 / 767 / 991 / 992 / 1199 / 1200 / 1440 七个边界，全部相等 |
| 零外部请求 | 过滤本地资源后的 `resource` 条目 | **0**（字体走系统栈，图标内联 SVG，无图床） |
| 行高 | 直接文本元素 `lineHeight - fontSize === 8` | 普查 **101 个**，违例 **0** |
| 全站最低对比度 | 正文 4.5:1 | **5.87:1**（时间戳 `#5e5e5e` 压选中评论卡 `#fbf0ff`） |
| 12px 占比 | 参考前两个案例的 30% 上限 | **41 / 101 = 40.6%**，见「新缺口 3」 |
| 触控目标 | ≥ 24px，主要动作 ≥ 44px | 主按钮 44、导航项 40、迷你动作 32（窄屏 44）、文本链接补到 24；勾选框本体 20，外层整行 44 或 56 可点 |
| 核心交互 | 逐条真跑 | 6 条全过（定位、解决、发评论、勾任务、滚动吸顶、键盘焦点），数字见 DECISIONS 第 8 节 |
| 单文件 | CSS / JS 内联 | `index.html` 34,141 字节，无外链标签 |

## 3. 新缺口（建议回填 GAP_RULES）

1. **TDesign 选型行没有 button 文章。** 输入、选择、表格、弹窗都有专篇，按钮没有。本站的按钮高度、圆角、hover 色只能从色板与派生值拼：高度 40 / 44 派生，色值取 Purple7 / Purple8 原文。建议给选型行补 button 篇，或把「按钮形态与尺寸」写进缺口表。
2. **TDesign 没有完整 spacing scale。** 只有基数、槽、边距与两个半档。本站按 8 的倍数自建了九档，和 TallyLane 的做法一致。建议在缺口表里把「8 的倍数序列」写成默认，避免每站各建一套。
3. **12px 占比 40.6%，超过前两个案例的 30% 经验线。** 营销页的信息标签多，时间戳、版本、参与人数、页脚都在 12 档。当前按 TDesign 桌面下限执行，可读性没问题，但视觉上偏密。若批次要求 ≤30%，应把评论时间与计数抬到 14 档；建议把「12px 只给元数据，不承载正文」写成明确口径。
4. **动效没有进场 / 出场差。** TDesign 只给三档单值 token。本站取 240 进、200 出，理由是「进场稍长」。这个分配目前每站自己写，建议补一句通用口径，或补两个 token。
5. **营销页的强调色面积没有可测口径。** README 要求 <5%，本站用截图像素统计（0.89%）。建议把这个方法写进验收说明，避免各站凭感觉。

## 4. 已知局限

- **没有后端。** 评论、解决状态、待办勾选都只存在当前页面，刷新回到初始三条评论与 1 / 4 待办。演示页不承诺保存，也没有「已同步」类文案。
- **客户与数字是虚构的。** 引语署名标了「示例客户」，三个结果数字是该客户自述口径，不代表产品实测；页脚写明「示例站点，产品与客户均为虚构」。
- **没有深色模式。** TDesign 给了 dark 色板，本页只做亮色。
- **窄屏标题自然换行。** 320 档标题从「写在同一张纸上」整段换行，避免拆开「一张纸」；更窄的视口（小于 320）不在验收范围。
- **评论区没有富文本。** 只接受纯文本，不支持 @ 与附件；示例只需要证明「评论贴着段落」这条链路。
- **实测环境限制。** 后台标签页里 CSS transition 会冻结，`getAnimations()` 有记录但 `currentTime` 停在 0；用 `Page.bringToFront` 让页面可见后才能量到推进。scroll 事件同理，必要时补一次 `dispatchEvent(new Event('scroll'))`。这是 harness 的行为，不是页面缺陷。
