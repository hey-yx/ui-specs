## 1. 合格线落点

| 项 | 判断依据 | 实测 |
| --- | --- | --- |
| 四档无横向溢出 | `scrollWidth === clientWidth` | 320 / 375 / 768 / 1280 四档全部相等（320=320、375=375、768=768、1280=1280） |
| 零外部请求 | `performance.getEntriesByType('resource').length === 0` | 四档都是 **0**（字体走系统栈，图形全 CSS，无图标库、无图床） |
| 行高 | 有直接文本的元素 `lineHeight - fontSize === 8` | 普查 **113 个**（320/375 档 112），违例 **0**；`<select>` 本身不计（本页无 select） |
| 12px 占比 | ≤ 30% | **15 / 114 = 13.2%**（320 档 15/113 = 13.3%） |
| 全站最低对比度 | 正文 4.5:1 | **4.73:1**（hero 眉题 `#8b6600` 压 `#f3f3f3`），背景按祖先链 alpha 合成后算 |
| 触控目标 | ≥ 44px | chip 44×44、主按钮 48、汉堡 44×44、公告关闭 44×44、分类行 44、导航项 44 |

## 3. 新缺口（建议回填 GAP_RULES）

1. **「首屏占比 85%」与版式件的 hero 定义冲突。**
   GAP_RULES 现有条款要求「hero 高度控制在一屏 85% 上下，让下一节露头」。Bento 原件要求的是「**fixed-height hero, not full viewport**」（`Hallmark 版式库 references/macrostructures/01-bento-grid.md`）。两条同时照做会得到一个 680px 高的格子，Bento 的节奏全毁。本站按版式件执行（hero 266px，占 800 高的 33%），**属例外**，建议 GAP_RULES 补一句：「版式件自带首屏高度定义时以版式件为准，85% 只约束单主张型的 hero」。
2. **金额「两位小数」没有分档。**
   合计、预算、进度该给两位；但明细行把 ¥6 写成 `¥6.00`、¥22 写成 `¥22.00`，一行里五个零，扫读反而慢。本站按现行规则全站两位（合规但偏噪），建议补档：「列表内条目可省 `.00`，合计/预算/差额保留两位」。
3. **深色底上的强调色没有换档条款。**
   GAP_RULES「色阶当文字」只写了「不达 4.5 的档换同族**深**档」。深色卡上要换的是**浅**档：`#8b6600` 压 `#181818` 只有 3.4:1，本站换 Yellow4 `#f5ba18`（10.08:1）。建议把该条改成「换同族相邻档，亮底走深档、暗底走浅档」。
4. **12px 上限与「行内时间戳」互相挤压。**
   明细日期列用 12px 时全站 12px 占比到 27.2%（31/114），只剩 3 个点余量；抬到 14px 降到 13.2%。缺口在于字阶里 12 与 14 之间没有档，而「标签用 12、列表元数据用 14」这个口径没有写下来。建议在 type 点补一句口径，别让每站各自试。
5. **TDesign 没有组件高度表。**
   输入框、按钮、chip 的高度全靠站点自己派生（本站 56/48/44）。中后台场景这是常用维度，建议在缺口表里点名，避免每站给出三套不同的控件高度。

## 4. 已知局限

- **数据不持久**：16 笔明细是页面里的常量，刷新回到初始状态。这是演示页，不是真应用；页面没有任何「已保存」的存储承诺（文案只说「已记」，不说「已同步」）。
- **没有日期控件**：需求只要「十秒记一笔」，所以日期固定今天，文案也按此收敛（不再写「日期默认今天」这种暗示可改的说法）。补记昨天的路径在应用里，不在这一页。
- **明细两列是列优先**：1000px 以上用 CSS `columns` 排 16 行，读序是先下后右（左列 11-08→11-05，右列 11-04→11-01）。按行优先要改成 grid + 显式分配，行数动态时容易错位，取舍见 DECISIONS §8。
- **窄屏导航是面板式**：N12 原件的窄屏口径是「链接 collapse」，本站做成下拉面板（带 `aria-expanded` + Esc 回焦），比纯折叠多一层可点区域，代价是展开时盖住首屏 213px。
- **没有深色模式**：TDesign 给了 dark 色板（`content/color/tdesign.tencent.com--dark.md`），本页只做亮色。深色批注卡是页面里的一个块，不是主题态。
- **768×900 首屏看不到表单底部**：内容自然长度所致（页面总高 2580），不是溢出，四档 `scrollWidth` 都等于 `clientWidth`。
- **实测环境两处限制**（不是页面问题，记下来防下次误判）：
  - 无头窗口里 `window.scrollTo()` **不派发 scroll 事件**（`window.__n` 计数为 0），N12 的收起只能用「滚到位 + 派发一次 scroll 事件」验证；真鼠标滚轮 `Input.dispatchMouseEvent` 在这个 harness 里超时。
  - 后台标签页 CSS transition 冻结，`getComputedStyle(nav).transform` 停在 `matrix(1,0,0,1,0,0)`；注入 `*{transition:none}` 后才量到 `-44px` 终态。截图与量测前必须先关过渡。
