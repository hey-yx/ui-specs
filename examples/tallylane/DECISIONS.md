## 1. 设计前提

需求只给了产品，区块与腔调是自己推的。推导路径：

1. 产品是**打开就要用的工具**，不是要说服人的落地页。但它被分到 Bento（营销向版式），所以这一页的定位是「**能直接用的产品首页**」：主张只有一句，其余全是可操作的面板。
2. 记账工具每天只发生四件事：**记一笔 / 看本月花了多少 / 看钱花在哪类 / 别超预算**。四件事平权，没有哪一件能撑起一句巨型标题——这正是 Bento 的选用标准（`briefs/layouts.md:22`「多块平权内容，没有单一巨型主张」）。
3. 因此页面没有 hero + 分区阵列，而是：一张 3×1 的主张块 + 六个功能/数据块，首屏之内就能真记一笔。
4. 腔调落成三处批注：公告条（「到了只提醒一次，不追着念」）、深色批注卡（「房租吃掉 85%。剩下的，吃饭、坐车、偶尔看场电影，够。」）、页脚一句（「记明白，就不慌了。」）。没有感叹号，没有「轻松理财」这类哄人的词。

## 2. 版式三件与落法

| 件 | 形态要点 | 为什么是它 | 落到本页 |
| --- | --- | --- | --- |
| **Bento Grid** | 不等跨距格子；固定高度 hero（不占满视口）；块间 12–24px；块内 CTA 用文字链 | 七个平权入口，靠大小差建立节奏而不是靠一张大图 | 6 列栅格，7 块：3×1 / 3×1 / 2×1 ×3 / 4×1 / 2×1；槽 16px；hero 只有一句主张，横向展开不放图 |
| **N12** | 公告条叠在真导航上，下滑收起、上滑放回，× 关掉不留缝 | 预算提醒是本产品唯一「时令性」的信息，值得一条常驻条 | 44px 公告条（`--banner-h`）+ 60px 导航条；下滑 `translateY(-44px)` 让导航吸附；× 关掉后 `--banner-h:0`，正文 `padding-top` 跟着收 |
| **Ft5** | 一句大字收尾，字标与链接压在小字里 | 记账页需要一个收束，而不是一张站点地图 | 「记明白，就不慌了。」36/48px；下面一行只有字标、版权、回到顶部 |

**Bento 怎么落到这一页**（1280 实测块高）：

| 块 | 跨距 | 内容 | 实测高 |
| --- | --- | --- | --- |
| hero | 3×1 | 眉题 + 「十秒，记一笔。」+ 一句说明 + 描边 chip | 266 |

**全站最低对比度 4.73:1**，出现在 hero 眉题（`#8b6600` 压 `#f3f3f3`）。这是强调色当小字的极限，再压浅一档就不过 AA，所以 hero 块底只用 Gray1，没有用更浅的米色。

黄当主色的三处冲突都处理过：

- 白字压 `#8b6600` 是 5.25:1，够 AA，所以公告条、选中 chip、主按钮直接白字，不必换深档。
- `#8b6600` 当文字压白是 5.25:1，合计数字、百分比可以直接用它（不需要换 Yellow8）。
- 深色批注卡上**不能**用 `#8b6600`（3.4:1），换同族 Yellow4，10.08:1。

## 4. 字阶与行高

字阶取 TDesign 第一、第二字阶原文值（`content/type/tdesign.tencent.com--fonts.md:49-60`：12 / 14 / 16 / 20 / 24 / 28 / 36 / 48 / 64），本页只用 5 档：

| 档 | 用在 | 行高 |
| --- | --- | --- |
| 48（仅 ≥1000px） | hero 标题、页脚大字、合计金额 | 56 |
| 36 | 窄屏 hero / 页脚 / 合计 / 预算百分比 | 44 |
| 20 | 块标题（h2）、批注正文 | 28 |
| 16 | hero 说明、主按钮 | 24 |
| 14 | 明细行、分类行、次级说明、导航 | 22 |
| 12 | 块标签、字段标签、分类占比（共 15 个文本节点） | 20 |

- 行高公式 `line-height = font size + 8` 取原文（`content/type/tdesign.tencent.com--fonts.md:67`，`:73-74` 给 `n = 8`）。落地用零特异性 `:where(body, body *){line-height:calc(1em + 8px)}`，让 `em` 按各自字号算；若写在 `body` 上会按 16px 算成 24px 固定值向下继承（上一批 81 处违例就是这个原因）。
- 字重只有 400 / 600 两档（`content/type/tdesign.tencent.com--fonts.md:81`）。
- 正文层：hero 说明 16px 起（`project-tdesign` 的下限），块内说明与明细行落 14px（TDesign 桌面 Body 档，`:52`）。
- 行长：说明段 `max-width` 22em（中文约 22 字），块内段落 26em（`project-tdesign`：中文窄栏 20–35 字），标 derived。
- 金额：`font-variant-numeric: tabular-nums`，两位小数、千分位（GAP_RULES「金额排版」条，标 derived）。

## 5. 间距与圆角

- 间距 8px 基数（`content/layout/tdesign.tencent.com--layout.md:65`「网格基数为 8px」），刻度 4 / 8 / 16 / 24 / 32 / 48 / 64，全站只用这一套。
- 栅格槽 16px（`content/layout/tdesign.tencent.com--layout.md:77`「槽默认为 16px」）——Bento 的块间距就是它，不再另取 12/20/24。
- 安全边距 24px（`content/layout/tdesign.tencent.com--layout.md:81`），320–359 档收 16px（同为 8 的倍数）。
- 壳宽 1180px（正文轨道 1132），派生：6 列 × 约 178 + 5 槽 × 16。
- 断点 320 / 375 / 768 / 1000（1000 起六列）；640 起两列、768 起 hero 与合计并排。断点值本身按 GAP_RULES 的「四档断点」口径取。
- 圆角两档：卡片 8px、控件 4px、胶囊 999px（库无通用 radius 规范，按 GAP_RULES 派生，成套自洽）。
- 组件高度派生：输入框 56px、主按钮 48px、chip / 导航项 / 分类行 / 关闭按钮 44px（触控目标按 WCAG 2.2 下限 44px，GAP_RULES「触控目标与焦点环」）。
- 发丝线 1px `#e8e8e8`（GAP_RULES「发丝线宽」条，派生）。焦点环 2px 实线 + 2px 偏移，用 `:focus-visible`。
- 纵向间距只由一层给：`.cell` 用 `gap` 而不是给子元素写 margin（`content/layout/every-layout.dev--stack.md:38-44`：间距是父级的事，元素自带 margin 会与父级 padding 叠成双份）。

## 7. 交互实测（浏览器实测，session `tallylane`）

四档溢出（`scrollWidth === clientWidth`）：

| 视口 | innerWidth | scrollWidth | clientWidth | 结论 |
| --- | --- | --- | --- | --- |
| 320 | 320 | 320 | 320 | 无溢出 |
| 375 | 375 | 375 | 375 | 无溢出 |
| 768 | 768 | 768 | 768 | 无溢出 |
| 1280 | 1280 | 1280 | 1280 | 无溢出 |

- **零外链**：`performance.getEntriesByType('resource').length === 0`，四档都是 0。
- **行高普查**：有直接文本的元素 113 个（320/375 档 112），`lineHeight - fontSize === 8` 违例 **0**。
- **12px 占比**：15 / 114 = **13.2%**（320 档 15/113 = 13.3%），上限三成。
- **最低对比度**：**4.73:1**（hero 眉题 `#8b6600` 压 `#f3f3f3`），背景沿祖先链做 alpha 合成后算。
- **字号分布**（1280）：12×15、14×84、16×3、20×6、24×1、36×1、48×3，全部在 TDesign 字阶上。

核心交互（前 → 后）：

| 交互 | 操作 | 实测结果 |
| --- | --- | --- |
| 记一笔 | 输入 `88`，分类「餐饮」，点「记下这笔」 | 合计 ¥3,760.00 → **¥3,848.00**；笔数 16 → **17**；餐饮 ¥176.00 → **¥264.00**；明细 16 → **17 行**；进度 75% → **77%**；输入框清空；确认行「已记：餐饮 ¥88.00 · 本月 17 笔」 |
| 分类切换 | 点分类卡「交通」 | 明细 17 行 → **3 行**，状态「交通 · 3 笔」，`aria-pressed=true` 落在交通行；再点一次回到 17 行、「全部 · 17 笔」 |
| 预算提醒触发 | 再记 ¥152（餐饮），合计到 ¥4,000.00 = 80% | 提醒块出现：「到 80% 了。剩 ¥1,000.00，还有 22 天，一天别超过 ¥45.45。」原「还差…」行隐藏；`aria-valuenow` 75 → **80**；进度条宽 75% → **80%**；预算卡高 404 → **404px**（不跳版） |
| 校验 | 空值 / `abc-0` / `0` 各提交一次 | 三次都拦下，行内提示「填个 0 到 99999 之间的金额。」，`aria-invalid=true`，明细行数不变（18） |
| 移动导航 | 320 档点汉堡 | `aria-expanded` false → **true**，面板 `display:none` → **flex**（213px 高）；点链接后自动收起回 false；Esc 收起并把焦点交回按钮（`document.activeElement === #nav-toggle`） |
| N12 收起 | y=400 下滑 / y=10 回顶 | `.nav` 加/去 `is-compact`：`translateY(0)` → **`translateY(-44px)`**，导航条吸到 0（顶栏高 44 → **0**）；回顶复原 |
| 公告关闭 | 点 × | `--banner-h` 44px → **0**，`body` 上内距 104 → **60px**，hero 顶 136 → **92px**，`scrollWidth` 仍 320（关掉不留缝） |

> 实测环境说明：无头窗口里 `window.scrollTo()` 不派发 scroll 事件、CSS transition 也会冻住（后台标签页不产帧）。N12 的收起是用「滚到位 → 派发一次 scroll 事件」验证的，位移读数前先注入 `*{transition:none}` 拿终态。这是环境限制，不是页面缺陷，见 FINDINGS。
