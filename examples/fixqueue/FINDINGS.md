# FixQueue 一线工单台：发现与取舍

## 一 交付范围

单文件 React 页面，React 18.3.1 + tdesign-react 1.18.6，import map 从 esm.sh 引，样式取 jsDelivr 上的 tdesign.css，版本写死。除这两处 CDN 不加载字体、图片、统计资源。数据在页面内生成 44 张工单，字段 10 列（单号、标题、设备/系统、部门、请求人、状态、优先级、处理人、等待时长、更新时间）外加操作列，四个状态、三个优先级。刷新回初始态。

## 二 六步里真正跑过的部分

第 1 到 3 步按指南读需求、读规范、记账，取值记录见同目录。第 4 步写完页面后，第 5、6 步的读数全部来自浏览器实测，原始数据落在 evidence.json。

## 三 宽度实测

八档宽度逐一实测，`document.documentElement.scrollWidth` 与 `clientWidth` 在每一档都相等，页面级横向溢出为 0：

| 宽度 | 形态 | 页面 scrollWidth / clientWidth | 表格容器 |
| --- | --- | --- | --- |
| 320 | 卡片 | 320 / 320 | 不渲染表格 |
| 375 | 卡片 | 375 / 375 | 不渲染表格 |
| 767 | 卡片 | 767 / 767 | 不渲染表格 |
| 768 | 表格 | 768 / 768 | 容器 718，内容 1220，横向滚动 |
| 769 | 表格 | 769 / 769 | 容器 719，内容 1220，横向滚动 |
| 991 | 表格 | 991 / 991 | 容器 941，内容 1220，横向滚动 |
| 992 | 表格 | 992 / 992 | 容器 942，内容 1220，横向滚动 |
| 1280 | 表格 | 1280 / 1280 | 容器 1230，内容 1230，不滚动 |

窄屏表格的策略是滚动容器，不是把表格压扁：768 到 1199 之间表格保底 1080px 宽，外层容器 `overflow-x: auto`，单号列 `fixed: left` 固定在左侧，容器带 `tabindex=0`、`role=region` 和可读的 aria 标签，聚焦时有 2px 品牌色描边。767 及以下整块换成卡片列表，卡片自带状态、优先级、等待时长与两个操作按钮。

## 四 对比度实测

逐项实测 19 处文本，全部达到判定线，没有靠估算。最低的三处都在浅灰底上的次级文字：表头 5.84:1、页脚 5.84:1、已关闭标签 5.84:1；状态标签与优先级标签单独测量：待处理 6.08、处理中 5.93、已解决 5.88、已关闭 5.84、紧急 6.31、较高 6.71、普通 6.48。

非文本项：控件边框 `#8b8b8b` 对白底 3.41:1，卡片内分割线只作装饰不参与判定，焦点环 `#0052d9` 对白底 6.54:1，分布条四段对白底分别是 3.12、4.47、3.16、3.41。

## 五 键盘走查

从页面顶部开始按 Tab，共 54 个停靠点，顺序是：跳转链接 → 品牌链接 → ⌘K 药丸 → 新建工单 → 四张统计卡 → 搜索框 → 状态、优先级、排序、每页四个下拉 → 导出 CSV → 表头全选 → 每行的复选框与详情、认领或解决 → 分页的每页条数与页码。每个停靠点都是 2px 可见焦点环。行内按钮 35x24 起，复选框 16x16 加内边距后命中区 28x28，达到 24x24 的下限。

弹层补了三件事：新建工单对话框打开后焦点落到标题输入框，Tab 在六个字段与两个按钮之间循环不外溢，Esc 关闭后焦点回到「新建工单」按钮；详情抽屉同样锁在面板内（认领这张与关闭之间循环），Esc 关闭后焦点回到行内「详情」按钮；⌘K 面板打开后焦点在搜索输入框，Esc 或再次 ⌘K 关闭后焦点回到药丸。

## 六 状态与交互

状态四种都造出来看过：搜索无结果与队列无工单是两种空态，文案不同；加载态有 7 行骨架，`aria-busy=true`，此时不渲染表格；表单空提交弹出三条字段错误加一条汇总，焦点落到第一个错误字段并带 `aria-invalid` 与 `aria-describedby`；新建成功与批量认领成功各弹一条 3000ms 全局提示。

真点过的交互 13 条，前后状态都记在 evidence.json：搜索、状态筛选、优先级筛选、排序（等待正序与更新时间倒序）、每页切 20 后的翻页、行选择、批量认领、单条认领、单条解决、撤销解决、详情抽屉、新建工单、导出 CSV。导出真的落盘：6792 字节、45 行（1 行表头 + 44 行数据）、带 BOM、列名与表头一致。

## 七 修掉的缺陷

- 分布条「已解决」段透明：段色读的是 `var(--seg-resolved)`，色板里只定义了 `--seg-done`，补别名后四段齐全。
- 弹窗与抽屉不锁焦点：Tab 会漏到页头，焦点回位也没有落点，补了 document 级捕获的 Tab 循环与 Esc 处理。
- 校验失败后焦点落空：原先同步找 `aria-invalid` 的元素，属性还没写上去，改成延时取第一个错误字段。
- 表格内滚动容器不可聚焦：补 `tabindex`、`role=region`、aria 标签与焦点环。
- 分页重复报总数：TDesign 自带「共 44 条数据」与自有「显示 1 至 12 张，共 44 张」重复，单位还不同，隐藏组件那一条。
- 操作列的竖向分隔线：1280 下表格不滚动时，固定列的分隔线成了孤立竖线，取消操作列固定，只保留单号列固定。
- 新建成功的提示文案原写「排在队首」，演示数据里有未来时间的更新时间，新单其实排在中间，文案改成「状态为待处理」。
- hero 数字与统计卡口径打架：hero 报未认领数，统计卡报待处理数，两者不同源，说明文字补上「其中 N 张未认领」把关系说清。

## 八 取舍

- 对话框关闭即销毁：原文默认不销毁，这里改成销毁，理由是每次新建都要干净表单，避免上次的错误提示和半截输入残留。
- 等待时长与更新时间右对齐：原文只要求等距数字，右对齐是按扫描效率加的，属于派生。
- 操作列不做固定：窄屏时宁可用滚动容器加单号锚定，也不把最后一列钉住，避免无滚动时出现孤立竖线。
- 演示数据里的更新时间有部分晚于当前时刻：为了让「等了 2 天 20 小时」这类等待时长成立，时间戳是按等待时长倒推的，个别行落在当天下午。这会让新建的工单按更新时间排序时排不到第一，因此提示文案不提「队首」。

## 九 没覆盖到的

- 横向滚动容器的键盘滚动：容器可聚焦、焦点环可见，但合成按键事件只能让页面纵向滚动，容器内 `scrollLeft` 没有变化。判断为测试环境对合成输入的限制（同一环境下合成鼠标点击也不触发 React 事件，只能用脚本派发），容器本身的键盘可滚能力没有在真实按键路径上验证。
- 真实后端与并发：全部是本地演示数据，没有请求、没有冲突处理、没有持久化。
- 深色模式：基准规范有深色篇，本案例只做浅色，页面没有主题切换。
- 屏幕阅读器实读：只做了语义与属性检查（角色、aria 标签、aria-live 播报），没有用 VoiceOver 实际朗读。
