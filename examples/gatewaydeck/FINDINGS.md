## 3. 键盘与焦点

- Tab 顺序：Skip → 品牌 → 导航 → 环境 → 告警 → 账号菜单 → 添加账号 → 页面范围按钮 → 刷新 → 图表按钮 → 搜索 / 筛选 / 排序 / 查看 → 路由开关 → 失败筛选 / 重试。所有按钮有 2px 可见轮廓。
- 账号抽屉：打开后焦点进入关闭按钮；Tab 在抽屉内循环；Esc 关闭并回到触发行的「查看」按钮。
- 添加账号对话框：打开后焦点进入账号名称；空提交时逐项报错，焦点回到第一个错误；Esc 关闭并回到「添加账号」按钮。
- 路由开关：`role="switch"`，Space 与 Enter 都能切换，`aria-checked` 与状态标签同步。
- 失败筛选：两个原生 select 可用键盘操作；筛选到 0 条时出现空态与「清除筛选」按钮，焦点不丢。
- 表格排序：排序按钮是原生 button，`aria-sort` 在 `ascending` / `descending` 间更新，视觉箭头跟着翻转。

## 4. 状态

| 状态 | 造法 | 观察 |
| --- | --- | --- |
| 加载 | 刷新 / 重试 / 签到 / 添加 | 按钮禁用并出现旋转图标，标签变为同步中 / 重试中 / 签到中 / 添加中 |
| 成功 | 签到或添加账号 | 表格与 KPI 同批更新，Toast 出现「撤销」 |
| 错误 | local-vllm 的失败记录点重试 | 1.2 秒后行内显示「重试失败：上游超时（504）」，Toast 说明仍返回 504 |
| 空态 | 失败表筛选 local-vllm + 502 | 0 条，空态文案与清除筛选按钮出现 |
| 空态 | 账号搜索无匹配 | 显示 0 / 12，空态出现，清除筛选可恢复 |
| 撤销 | 签到、路由开关、添加账号 | 数据回到操作前，Toast 显示「已撤销…」 |
| 横幅收起 | 向下滚动 | 顶栏整体上移，状态横幅收起；向上滚动恢复 |
| 横幅关闭 | 点 × | 横幅 display:none，主区上边距从 116px 收到 72px |

添加账号的空提交实测报出 3 个错误（名称、端点、Key），焦点落在 `accName`；提交成功后账号数从 12 变 13，撤销后回到 12。

## 6. 动效

- 70ms 微交互，110ms 淡入淡出，150ms 小展开，240ms 弹层 / Toast / 横幅，400ms 大展开。曲线全部来自 Carbon：标准 `cubic-bezier(0.2, 0, 0.38, 0.9)`、进场 `cubic-bezier(0, 0, 0.38, 0.9)`、退场 `cubic-bezier(0.2, 0, 1, 0.9)`。
- `prefers-reduced-motion: reduce` 下抽屉、Toast、顶栏实测 `transition-duration: 1e-05s`（0.01ms），没有位移动画。
- 抽屉与对话框关闭先加 `is-closing`，过渡结束再 `hidden`；不是直接 display:none。

## 7. 设计点盲测

| 题 | 答 | 本案落地 |
| --- | --- | --- |
| Carbon 对界面状态过渡的无障碍兜底有什么要求？ | 永远提供状态过渡的替代方案；移动端和平板考虑简化或减弱动效；始终保留用静态方式传达同样信息的手段（`content/motion/carbondesignsystem.com--motion.md:249`）。 | 减弱动效下过渡压到 0.01ms；KPI、表格、图表数据表在无动效时仍可读。 |
| NN/g 说进入和退出屏幕的时长有什么差别，弹窗例子是多少？ | 进入比退出稍长；弹窗约 300ms 进入，200 或 250ms 退出（`content/motion/nngroup.com--animation-duration.md:84`）。 | 本案基准是 Carbon，用 Carbon 的 240ms 弹层档与独立的进场 / 退场曲线，不套 NN/g 的 300 / 200 数值。 |
| W3C 的 ease-out 等价于哪条曲线？ | `cubic-bezier(0, 0, 0.58, 1)`（`content/standards/w3c--css-easing-1.md:138`）。 | 本案用 Carbon 自己的标准 / 进场 / 退场曲线；W3C 曲线只作原则对照。 |
| 等待过程按等待时长怎么分档？ | 不到 1 秒不显示加载态；1 到 3 秒用不定量加载态；3 秒以上用定量进度；超过 10 秒转后台任务（`content/patterns/ui-specs--test-walkthrough.md:35`）。 | 刷新、重试、签到、添加都在 1 到 1.2 秒，用不定量旋转图标；失败保留原因和下一步。 |
| 底线复测看哪些数值？ | 正文 4.5:1，大字与非文本 3:1，焦点态与非焦点态 3:1，指针目标不小于 24 × 24 CSS 像素（`content/patterns/ui-specs--test-walkthrough.md:47`、`content/a11y/w3c--wcag-2.2.md:907`）。 | 逐项实测见第 2 节与第 3 节；最小可点控件 32px，主操作 40 / 44px。 |

TDesign 的 768 / 992 / 1200 断点与优设的 8px 间距 checks 不适用于本案：基准是 Carbon，页面用 Carbon 的 320 / 672 / 1056 / 1312 断点与 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 间距。

## 8. 未验到与已知问题

1. **表格降级点**：账号表在 768 以下转卡片，比 Carbon 的 672 断点提前；原因是 768 宽时 6 列表格在 684px 容器里会横向溢出。该规则标 derived，需在后续版本决定是否保留。
2. **图表库**：图表是内联 SVG，未引入第三方图表库；单文件案例页按内联 SVG 处理，几何参数与颜色在本页控制。
3. **数据不持久**：账号、签到、路由开关、添加账号都在内存里，刷新恢复初始数据。
4. **字体回退**：IBM Plex 未随页面加载，实际使用系统里已安装的 IBM Plex，缺失时回退 Helvetica / Arial / 苹方。
5. **未测浏览器**：只在 Chromium 测过，Safari 与 Firefox 未跑。
6. **命名**：`gatewaydeck.com` 与 `.net` 已注册但访问 404，没有上线产品；`gatewaydeck.dev` / `.io` / `.app` 可注册（RDAP）。npm 与 GitHub 无同赛道同名产品；商标未查。
7. **剪贴板**：复制端点按钮依赖浏览器剪贴板权限，测试环境未验证成功写入。
