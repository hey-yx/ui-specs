# SwimBoard · 实测与缺口记录

本文件中的实测来自子代理自验。主会话复验见 `../VERIFIED.md`。

## 1. 合格线落点（可核验事实，均为本轮浏览器实测）

| 项目 | 结果 | 测法 |
| --- | --- | --- |
| 320 / 375 / 768 / 1280 横向溢出 | 四档 `scrollWidth === clientWidth`（320/320、375/375、768/768、1280/1280） | CDP 改视口后读 `documentElement` |
| 行高（字号 + 8） | 0 违例（1280 下 87 个可见文本节点，375 下 46 个） | 遍历含直接文本的节点，比较 `lineHeight - fontSize` |
| 可见文本对比度 | 最低 5.56:1，0 处不达 AA（1280 扫 80 个节点，375 扫 34 个） | 逐节点取计算色，向上找实底背景，按 WCAG 相对亮度算 |
| 非文本对比 | 控件边界 3.41:1、焦点环 3.41:1 以上、进度轨 3.41:1 以上 | 同上公式，取边框/图形色 |
| 字号档位 | 12 / 14 / 24 三档，无第四档 | 统计可见文本节点字号分布 |
| 12 小档占比 | 1280 下 26.4%，375 下 23.9% | 12 号节点 / 可见文本节点 |
| 控件高度 | 按钮 32、行内按钮 32、选择器 32；粗指针或窄屏 44 | computed 高度 |
| 控件内文字上下留白 | 主按钮 5/5、行内按钮 5/5、选择器值 5/5 | 文字盒与控件盒的上下间距 |
| 选择器弹层 | `.t-popup__content` 白底、有阴影、圆角 4，不是透明层 | 打开后读计算样式 |
| 弹窗 | 1280 下 480×360，375 下 319×502、左边距 24；白底、圆角 8、遮罩 rgba(0,0,0,.6) | computed |
| 弹窗校验 | 空标题提交：输入框红框、提示文字 rgb(173,53,47)、role=alert、焦点回到输入框；弹窗高度 360 不变 | computed + 焦点检测 |
| 弹窗控件 | 375 下标题输入 44、两个下拉 44、两个按钮 44（只抬根容器） | computed |
| 台账 | `scripts/check-ledger.py` 通过：66 处引用，20 处带值、46 处原则、0 处缩写，退出码 0 | 脚本输出 |
| 375 首屏完整任务 | 5 条，其中 4 条带可执行按钮 | 逐行量 `bottom <= innerHeight` |
| 紧凑行高 | 72（含描边），未超 80 | 逐行量 rect |
| 首屏主操作 | 首行按钮 y=263（375×667），远在折叠线之上 | rect |
| 资源请求 | 3 个外部资源：官方全量 CSS、esm.sh 的 vue、esm.sh 的组件库 bundle（+ 一次 favicon） | `performance.getEntriesByType('resource')` |

自验环境：Chromium（本机 CDP），session `uispecs-swimboard-20261114`；无头环境下库组件的入场过渡依赖帧回调，需先开启焦点模拟再量过渡，否则会读到起始帧（这是采集环境的事，不是页面问题）。

移动端形态判定：desktop-first。TDesign 没有官方移动队列 / 看板模式；375 与 768 的紧凑列表是页面派生（同一份数据、另一套行结构），不是库原生能力，标 `desktop-first`。

## 2. Hallmark 后置检查

pre-emit 六轴：P5 H4 E4 S5 R5 V4（哲学：工作台就是产品本身，无介绍层；层级：24 / 14 / 12 三档 + 字重字色；执行：四档、行高、对比、控件留白全过；具体性：状态进度轨与行内下一步是本页独有；克制：无 hero、无 KPI 三连、无装饰图形；variety：与批内另一站的骨架不同，但同属工具型）。

slop test 与本稿相关的条目，逐条结论：

- 卡片左侧粗色条：初稿有 3px 色条，判为 tell，已整条删掉，状态改由列分组 + 进度轨 + 状态文字承担。
- 页内颜色：初稿有 `.palette__scrim`、回执条文字等 5 处裸值，已全部提到 `:root` token（遮罩、反白文字、两层阴影），现在样式表内除 token 定义外没有裸色值。
- 焦点环不参与过渡（`outline` 直接出现），无 `transition: all`，无 hover 缩放，无回弹曲线。
- 弹窗错误提示槽预留高度（`min-height`），出错时弹窗不下跳。
- 导航不是「wordmark + 四个链接 + 右侧按钮」的默认指纹（N13 搜索胶囊），页脚不是四列链接（Ft4 一行注记）。
- 无假浏览器窗框、无渐变文字、无 emoji 当图标、无虚构业绩数字（任务数据在页脚明确标注为虚构示例）。
- 移动端：clickable 文本全部单行（按钮加 `white-space: nowrap`），四档无横向滚动，`overflow-x: clip`。
- 字体族只有两套（正文系统字族 + 编号/页脚的系统等宽），不超过三套；标题不用斜体。
- 字色对比：正文、次级、三级都按实际底色复算，无「浅灰压浅底」。

## 3. 数值缺口与替代（逐条）

| 维度 | 处理 | 依据 |
| --- | --- | --- |
| 圆角 | 派生 4（卡/控件）/ 8（弹窗/回执条）两档 | GAP_RULES「圆角」：库无通用 radius 规范 |
| 控件高度 | 派生 32 一档，按钮与选择器同高 | GAP_RULES「组件尺寸」 |
| 触控目标 | 派生 44，粗指针与 ≤991 生效，只动根容器 | GAP_RULES「触控目标与焦点环」 |
| 焦点环 | 派生 2px 实线 + 2px 偏移，强调色 | 同上 |
| 阴影 | 面板 `0 24px 48px -24px rgba(0,0,0,.5)`、回执条 `0 8px 24px -12px rgba(0,0,0,.45)` | GAP_RULES「组件阴影与底边」；库 CSS 未给这两件（自建件） |
| 遮罩 | rgba(0,0,0,.6)，与库弹窗同值，全站一档 | 实测库 computed；GAP_RULES「弹层遮罩」要求全站一档 |
| 行高 | 字号 + 8 逐元素推导（12→20、14→22、24→32） | 基准规范给公式，不给逐档 px |
| 三级文字 | 库 40% 黑压白底约 2.9:1，换成同族 Gray9 #5e5e5e（6.49:1） | GAP_RULES「色阶当文字」：文字换同族深档 |
| 占位文字 | 同上换 #5e5e5e | 占位也按正文算 |
| 边框 | 库 level-1 只有 1.23:1，改 Gray7 #8b8b8b（3.41:1）；Gray3 只做分隔线 | 同上 + 非文本 3:1 |
| 语义色 | 成功/警告/错误文字映射到各自 7 档深阶 | 同上：hover/active 与语义 token 按实际底色复算 |
| 数字字体 | TCloud Number 零外部请求拿不到，用系统等宽 + `tabular-nums` 近似 | GAP_RULES「数字字体」，标降级 |
| 图 | 无图表，不涉及图表库 | 指南第 5 步：纯测试页可不引库 |

## 4. 新缺口（建议）

1. 状态进度轨（stepper / progress rail）没有组件规范：TDesign 的组件文章里没有「卡片内的四段状态轨」，本页按 8px 基数与色板自绘。建议回填一条组件级设计点，给出轨宽、段距、三态（已过/当前/未到）色阶。
2. 看板列数没有版式规则：1280 四列、992 以下转列表，是按内容宽度和 TDesign 断点推的，不是规范给的。建议在版型原型里补「看板类页面的列数与折叠断点」。
3. GAP_RULES 的遮罩档位与库默认值不一致：规则写 0.45 上下，TDesign 弹窗实测 0.6。本轮取库值并全站统一，建议在缺口规则里注明「库有官方遮罩时以库值为准」。
4. 「一屏可行动对象数」这类密度判据只在维护技能里，内容库正文没有对应条目；建议并入版型原型的验收判据。

## 5. 设计点 checks 逐题自答

- 界面配色框架 · Harvest 的 hover 与选中怎么用同一个主题色区分：选中态只降亮度、饱和度不变；hover 只降饱和、亮度不变，各自只动一个维度（`content/howto/learnui.design--color-in-ui-design-a-practical-framework.md:242`）。本页把这条落到橙色阶：hover 走 brand-8（更深一档），浅底走 brand-1（更高亮度、更低饱和）。
- 界面配色框架 · 基准色相盘按什么间隔取、饱和度亮度取多少：色相 30° 等间隔，全部 100% 饱和度与 100% 亮度（同文 `:282`）。本页只用一个色相（橙）的十级阶，不铺多色相。
- 视觉层级 · 字号最多几档、各档范围、为什么：最多三档（小 / 中 / 大），正文 14 至 16、副标题 18 至 22、标题最大到 32；三档够拉开层次又不糊（`content/howto/nngroup.com--visual-hierarchy-ux-definition.md:76`）。本页 12 / 14 / 24，把「最大」让给冲刺标题一处。
- 视觉层级 · 什么页面用 F 型扫描、视线怎么走：文字密集页（如博客），先沿左侧竖扫找关键词，遇到感兴趣的内容再横读，整体像 F 或 E（`content/howto/awwwards.com--understanding-web-ui-visual-hierarchy.md:48`）。本页据此把列头、卡标题、元信息压在同一条左轴，扫读只走一列。
- 布局模式 · Stack 用什么机制注入纵向间距：父级用相邻兄弟选择器 `* + *` 只给「前面有元素」的那个加间距，不留多余 margin（`content/layout/every-layout.dev--stack.md:44`）。本页用 flex + gap 达到同一目标，子元素不写散 margin。
- 布局模式 · Switcher 什么时候从横向切纵向：父容器宽度小于设定断点时切成单列（`content/layout/every-layout.dev--switcher.md:61`）。本页的等价做法是 992（TDesign md 断点）以下四列看板转单列紧凑列表。
- 动效落地 · 33 条配方里多少处默认曲线是 `cubic-bezier(0.22, 1, 0.36, 1)`：31 处（`content/motion/ui-specs--motion-implementation.md:24`）。本页只借配方的属性与顺序，曲线一律用 TDesign 的三条定值。
- 动效落地 · 菜单下拉入场出场各多少毫秒：250 进、150 出（同文 `:28`）。本页按本库基准规范改写成 240 进、200 出，两笔账分开记。
- 就地状态动效 · 文本切换多少毫秒、模糊多少：200ms、模糊 2px（`content/motion/transitions.dev--04-text-states-swap.md:39` 到 `:42`）。本页取它的位移 + 模糊 + 透明度三件，毫秒换成本库的 240。
- 就地状态动效 · 数字 pop-in 的模糊与曲线：模糊 2px，曲线 `cubic-bezier(0.34, 1.45, 0.64, 1)`（`content/motion/transitions.dev--02-number-pop-in.md:51`）。本页没有数字滚动，未采用它的回弹曲线（中后台状态变化不用回弹）。
- 浮层与转场 · 菜单下拉开关时长与起始缩放：开 250、关 150、起始 scale 0.97（`content/motion/transitions.dev--05-menu-dropdown.md:43`）。搜索面板照这个形状做成 0.97 起，时长 240/200。
- 浮层与转场 · 弹窗开关时长与起始缩放：开 250、关 150、起始 scale 0.96（`content/motion/transitions.dev--06-modal.md:38`）。本页弹窗交给库组件，不自写缩放，故未采用 0.96。
- 反馈与通过标准 · 等待过程怎么分档：不到 1 秒不显示加载态，1 至 3 秒不定量，3 秒以上定量进度，超过 10 秒转后台任务（`content/patterns/ui-specs--test-walkthrough.md:35`）。本页改动都在本页完成、无等待，因此不加载入态；失败与离场用回执条说明。
- 反馈与通过标准 · 底线复测看哪些数：正文 4.5:1、大字与非文本 3:1、焦点态与非焦点态 3:1、指针目标不小于 24×24（同文 `:47`）。本页最低 5.56:1，目标 44。
- 中文文案与排版 · 数字与单位之间加空格的例外：度数和百分比不加空格（`content/markdown/github.com--chinese-copywriting-guidelines.md:64`）。页内「11 月 9 日」「SB-124」「6.71:1」按此处理：中文与数字之间加空格，编号与比例不加。

## 6. 外部依赖与范围

- 外部 CDN：官方全量 CSS 走 jsDelivr（tdesign-vue-next 的 dist），框架与组件库走 esm.sh（`vue@3.5.45`、`tdesign-vue-next@1.20.11?bundle&external=vue`）。本机 localhost 冷启动到可交互约 6 至 10 秒（组件库 bundle 约 1.4MB），首次访问受网络影响；离线打不开。
- 演示存储：全部任务数据在页面内生成，改动只存在当前标签页的内存里，刷新即恢复初始 10 项；没有 localStorage、没有后端、没有接口。
- 多用户未接入：页面固定一个「我」（林乔），认领与推进只作用在本页数据；没有账号、权限、并发、冲突处理，也没有跨人实时同步。
- 数据为虚构示例，页脚已标注；不冒充真实团队业绩。

## 7. 已知局限

1. 错误提示用 `role="alert"` 区域出现并配合焦点回到输入框来播报；标签用 `<label>` 包裹控件拿到可访问名。库不把 `id` 与 `input-props` 透传到原生 input，所以没有加 `aria-describedby`，读屏器播报依赖 alert 区域。
2. 弹窗的开合动画由库负责，本轮只验了开合结果（关闭后 `.t-dialog__ctx` 为 `display:none`）与遮罩，没有逐帧量库内部过渡。
3. 认领只支持「认领给我」，没有转派、释放、批量认领。
4. 看板不支持拖拽换列，推进只能通过行内按钮（有意为之：拖拽无键盘等价物）。
5. 320 下首屏可行动任务 4 条，但任务标题会被省略号截断（单行），完整标题要靠搜索面板或加宽窗口。
6. 编号与页脚用系统等宽字族，不是规范点名的 TCloud Number（降级处理）。
7. 搜索面板的焦点锁只在面板内两个可聚焦元素之间循环（输入框与关闭键），结果项用 `aria-activedescendant` 而非 roving tabindex。
8. 本轮只做冒烟级自验（1280 / 375 截图、四档溢出、一条主流程、三处过渡开与关、对比度与行高普查）；键盘全量走查、空态/加载/错误逐态与四档截图由主会话独立复验。
