基准规范：TDesign（`site/dist/ai/guide.md:27`）。数值出处逐条在 `DECISIONS.md`，这里只记「基准规范没给、我怎么办」。

## 1. 本稿相对合格线的落点（可核验事实）

- **四档无横向滚动**：`scrollWidth / clientWidth` = 320/320、375/375、768/768、1280/1280。
- **零外部请求**：`performance.getEntriesByType('resource').length === 0`；文件里 `http` 引用数 0；图标全部内联 SVG，字体用系统栈。
- **行高全量普查**：遍历含直接文本的节点，320 档 156 个 / 375 档 156 个 / 768 档 138 个 / 1280 档 158 个，违例 0（判定：`|行高 − (字号 + 8)| ≤ 0.6px`）。
- **对比度**：非禁用文字最低 5.69:1（逾期标签 `#ad352f` 压 `#fff0ed`），正文 17.40:1，次要文字 6.48:1，主按钮白字 6.54:1；非文本最低 3.12:1（评审圆点），输入描边 3.41:1。禁用态 2.85:1，只出现在「已完成」卡片的推进按钮上。
- **强调色面积**：1280 默认视图 0.51%，弹窗打开 0.83%，均 < 5%。
- **字号 3 档**：12 / 14 / 20，20px 元素 2 个（页面标题、完成率）。
- **基准规范覆盖**：色彩、字阶、行高公式、字重、字色、8px 网格、侧栏宽、断点、动效时长与曲线、图标栅格 —— 全部有原文行号；无法从基准规范取的维度集中在圆角、组件尺寸、阴影、遮罩、响应式下限，见 §2。
- **交互实测 14 组前后数字**（明细见 `DECISIONS.md` §8）：视图筛选（12→3→2→0→12）、项目筛选（12→4）、周期切换（12/33%→10/90%）、新建任务三态（12→12→12→13）、抽屉开合（x 1280→880）与焦点陷阱（8 次 Tab 不出框）、状态流转（3-4-2-4→3-3-2-5，31%→38%）、⌘K 搜索（13→1 / 2 / 0）、复制摘要（成功 / 拒权两态）、移动端侧栏（`aria-expanded` false→true，卡片 12→3）。

## 3. 新缺口（指南没覆盖、被迫自定的维度）

1. **工作台/看板没有组件规格**。基准规范是中后台页面级规范（导航布局、栅格、断点），没有「看板列宽、任务卡高度、卡内信息层数、列头高度」。本稿只能成套自定（列等分、卡高 108–116px、卡内 3 段：标签 / 标题 / 元信息）。
   → 建议回填一条「看板/列表容器」缺口规则：列宽按可用宽度等分，卡内信息限定 3 段（身份、主体、元数据），不逐卡加字段。

2. **基准规范最小页面宽 768（`content/layout/tdesign.tencent.com--layout.md:133`）与「320/375 不得横向溢出」的验收冲突**。指南只说「可访问性底线高于风格」，没给这种冲突的处置口径。本稿按底线优先，<768 改抽屉侧栏 + 单列堆叠，标 derived。
   → 建议回填：「基准规范断点下限高于验收档时，按下限以下重新组织布局并记 derived，不许出现横向滚动」。

3. **选中态强度没有判断标准**。库里有交互状态的原则（`content/principles/polaris.shopify.com--interaction-states.md:40`），但没有「选中片底色差多少才算可辨」。第一版用 `#f2f3ff` 在白底上几乎看不出，只能靠视觉复核发现。
   → 建议回填：「选中态至少一层同族浅色底 + 1px 主色描边，文字压底复算 ≥4.5」。

4. **项目选型表有两行重叠**（`site/dist/ai/guide.md:26` 协作与项目管理工具 → Atlassian；`site/dist/ai/guide.md:27` 中文产品 UI 含协作 → TDesign），缺 tie-break。本稿取「界面语言优先」（全中文界面、14px 中文正文）。
   → 建议回填一条选用标准：产品语境行重叠时，按界面文案语言与字符宽度优先；两者都非中文时再看功能类型。

5. **焦点环颜色未指定**。缺口表给了 2px/2px 的规格，没给颜色。本稿取基准规范强调色（对白 6.54:1、对画布 5.90:1）。
   → 建议回填：「焦点环取基准规范强调色，并对所在的两种底色各复算 ≥3:1」。

6. **应用型页脚无规范**。TDesign 只定义 footer 是「辅助信息区」（`content/layout/tdesign.tencent.com--layout.md:37`），没有工作台底栏的信息构成。本稿用 12px 署名条（数据来源 / 任务数 / 快捷键 / 版本）。
   → 可回填也可不回填：这是项目结构决策，不涉及数值。

7. **空状态与校验的「行为」只有非基准规范模式可抄**。GOV.UK 校验、Carbon 弹窗、Primer 空状态、APG 对话框都是别的体系；指南允许「其余来源只取原则」，但没说跨体系的**文案措辞**能不能照抄。本稿抄了行为（错误摘要置顶并聚焦、Esc 关闭、焦点归还、空状态只给一个主行动），中文文案自己写，不搬英文原句。
   → 建议明确：「跨体系照抄行为与结构，不照抄措辞与数值」。

## 4. 已知局限

1. **剪贴板成功态是打桩验证的**。测试环境是后台/无焦点窗口，Chromium 直接拒绝 `navigator.clipboard.writeText`，`document.execCommand('copy')` 也返回 false（`document.hasFocus() === false`）。真实拒绝路径已实测（toast「浏览器拒绝了剪贴板访问，请检查站点权限」）；成功路径（label 变「已复制」+ toast + 2s 复位）是在页面内打桩 `clipboard.writeText → Promise.resolve()` 后测到的，**没有读到真实剪贴板内容**。
2. **没有拖拽**。移动任务走「卡片推进按钮」+「详情抽屉里的状态组」，依据 TDesign 状态流转「通过列表摘要进行状态流转」（`content/patterns/tdesign.tencent.com--backoffice-tasks.md:158-164`）。好处是键盘与触屏都能用、可测；代价是习惯了 Jira/Trello 拖拽的人会觉得少一手。
3. **数据是 12 + 10 条示例，刷新即重置**。需求明确「不做服务端」，本稿也没有做本地持久化，所以页脚写的是「示例数据 · 不上传服务端」，不写「已保存」。
4. **没做暗色模式**。基准规范有 dark 篇（`content/color/tdesign.tencent.com--dark.md`），不在本次需求范围内，未取任何暗色值，页面也没有假的切换开关。
5. **没有屏幕阅读器实测**。做了 ARIA 结构（`role="dialog"` + `aria-modal` + `aria-labelledby`、`aria-pressed`、`role="combobox"` + `aria-activedescendant`、`role="status"` 播报）与纯键盘实测（Tab 陷阱、Esc、⌘K、焦点归还），但没有 VoiceOver/NVDA 走查。
6. **只测了 Chrome**。Safari/Firefox 未测，`dvh` 单位、`:has()` 选择器、`input[type=date]` 的本地化外观都可能有差异（`:has()` 在 2023 年后的三大引擎都已支持，但本稿未实机验证）。
7. **768–991 档的 2×2 看板是判断，不是实测结论**。4 列在 704px 可用宽度下每列 176px 会导致标题频繁折行，故选 2×2；没有做用户测试验证哪种更好扫。
8. **抽屉里的「活动」是示例记录**（认领 / 移到某列），没有时间戳，也没有真实操作日志 —— 因为数据是静态的，不假装有历史。
